# 设计 v2.9：渠道自动调度落地（v2.1 调权闭环的 confirm/auto 阶段）

日期：2026-07-28。本文是 docs/design-v2.1-auto-tuning.md 的落地补充——三档模式、质量评估、护栏、命中率判据、执行链路均以 v2.1 原稿为准，不重复；本文只记 v2.8 多站点之后的适配决策与批次拆分。

## 1. 现状

- observe 档（v2.1-B1）已上线：评估引擎按周期产出建议并做 30 分钟事后回填，生产已积累数据；报表 API `/api/dashboard/tuning/report` 可用，**无页面**。
- confirm / auto 档未建；渠道命令执行链路（命令→心跳认领→agent 执行→审计）现成。

## 2. 多站点适配决策（相对 v2.1 原稿）

1. **策略与模式按站点**：渠道是站点属性；评估数据挂采集实例名下、恰好等价站点。调权中心页跟随顶栏站点切换。原稿"跨实例不联动"升级为"跨站点不联动"。
2. **执行目标=约定控制机（用户拍板，简单优先）**：沿用 B4 的"站点成员字典序第一台（`<站点>_1`）"约定，不做 agent 能力上报建模。约定失效（控制机换机/命名不规范）时人工档看得见改得回；auto 档靠"命令过期哨兵"兜底（见 §3）。能力上报（心跳带 `channel_control_enabled`）记为后续可能项，auto 实际运行中若哨兵频繁触发再启动。
3. **最小可用集按站点独立计算**：每站点健康渠道 <2 时该站点禁止任何降级动作（原稿护栏 1 的站点化表述）。

## 3. 新增护栏：auto 命令过期哨兵

auto 档引擎周期内检查自己创建的渠道命令：**存在到期未执行的 → 立即暂停该站点 auto（回落 confirm）并产出告警**（复用告警/通知链路）。覆盖"命令发给不能执行的机器而静默卡死"的场景，零新机制（命令过期状态现成）。人工重新开启 auto 前应排查控制机配置。

## 4. 批次拆分

| 批次 | 内容 | 对应 v2.1 原稿 |
|---|---|---|
| **v2.9-B1** | Web 调权中心（按站点：模式三选一/策略表单/建议流水+证据+事后徽标/命中率报表卡）+ confirm 采纳链路（采纳→既有渠道命令,确认框,审计） | v2.1-B2 |
| **v2.9-B2** | auto 执行器 + 全部护栏（含 §2.3、§3）+ before/after 记录与一键回滚 | v2.1-B3 |

**节奏纪律（沿用原稿）**：B1 部署后先看命中率报表（判据：持续 ≥85% 且无最小可用集险情）；confirm 档用一阵体感核对；数据与体感都过关才开 auto。开工 B2 前先在生产 curl 报表确认数据形态。

## 5. 明确不做

agent 控制能力心跳上报（记为可能项）；跨站点联动调权；评分型质量模型（维持阈值型可解释规则）；探测数据并入（v1.1 探测批次仍挂起，落地后再议）。
