# 设计 v2.9：渠道自动调度落地（v2.1 调权闭环的 confirm/auto 阶段）

日期：2026-07-28。本文是 docs/design-v2.1-auto-tuning.md 的落地补充——三档模式、质量评估、护栏、命中率判据、执行链路均以 v2.1 原稿为准，不重复；本文只记 v2.8 多站点之后的适配决策与批次拆分。

## 1. 现状

- observe 档（v2.1-B1）已上线：评估引擎按周期产出建议并做 30 分钟事后回填，生产已积累数据；报表 API `/api/dashboard/tuning/report` 可用，**无页面**。
- confirm / auto 档未建；渠道命令执行链路（命令→心跳认领→agent 执行→审计）现成。

## 2. 多站点适配决策（相对 v2.1 原稿）

1. **策略与模式按站点**：渠道是站点属性；评估数据挂采集实例名下、恰好等价站点。调权中心页跟随顶栏站点切换。原稿"跨实例不联动"升级为"跨站点不联动"。
2. **执行目标=约定控制机（用户拍板，简单优先）**：沿用 B4 的"站点成员字典序第一台（`<站点>_1`）"约定，不做 agent 能力上报建模。约定失效（控制机换机/命名不规范）时人工档看得见改得回；auto 档靠"命令过期哨兵"兜底（见 §3）。能力上报（心跳带 `channel_control_enabled`）记为后续可能项，auto 实际运行中若哨兵频繁触发再启动。
3. **最小可用集按站点独立计算**：每站点健康渠道 <2 时该站点禁止任何降级动作（原稿护栏 1 的站点化表述）。

## 3. 评估模型定稿：值班调度（2026-07-29 三轮讨论收敛）

演进脉络：渠道级绝对阈值（v2.1 原稿）→ 模型组内比较（用户指出调度=同模型组内相对排序）→ **值班模型**（用户确认两条部署现实：一渠道一模型；每模型平时只有优先级最高者在岗吃流量）。最终塌缩为本节规则，权重算法/组内健康判定/阶梯回升三块全部出列。

**核心**：每模型的启用渠道按优先级排成梯队，只有排头在岗吃流量。引擎**只评在岗者**（有流量才可评估；备胎无数据不评），坏了降到队尾换下一个顶上，被换下的按指数退避拉回试岗。

### 判定（对在岗渠道，窗口 15 分钟，样本 ≥20 才评）

1. 错误率 ≥15% 连续 2 周期（防抖）；
2. 熔断：错误率 ≥50%，1 周期即触发；
3. 延迟：P95 超过**自身近 24h 基线**2 倍且 ≥10s，连续 2 周期。（值班模型下同组无同行流量可比，延迟对照只能纵向自比。）

### 动作（只动优先级，权重旋钮出列）

- 前提：梯队存在启用备胎，否则不动+告警"无备份渠道"（备胎健康未知是必然——无流量无数据；未知优于确定坏，切换后 15 分钟内真实数据给出答案）；
- 降级 = 优先级降到队尾（全梯队最低值减 1），备胎自动接岗、接岗即入监；连锁劣化就连锁换班；梯队用尽 → 停手+告警"全梯队劣化"；
- 恢复 = **试岗制**：降级 60 分钟后自动升回原岗放真实流量试 2 周期，正常留任，仍坏降回并退避翻倍（60/120/240min…封顶 24h）；人工一键回岗随时可用。试岗即"真实流量探针"，震荡由退避间隔压制。

### 护栏（全程有效）

人工改动 24h 静默、混布渠道（models>1）跳过记档、同渠道动作间隔 ≥10min 且每日 ≤6 次、agent 离线整站不动作、只碰启用渠道、每笔记 before 可一键回滚、动作全走渠道命令链路留审计。

### 参数默认值（页面可配）

窗口 15min / 样本 20 / 错误率 15% / 熔断 50% / 延迟 2×且≥10s / 防抖 2 周期 / 首次试岗 60min 退避×2 封顶 24h / 试岗观察 2 周期 / 冷却 10min / 每日 6 次。

**影响**：引擎重写后 observe 命中率重新积累，旧渠道级规则数据作废；auto 开启判据（≥85%）基于新引擎数据。此改造为 **v2.9-B2**（纯 server 侧，另需新增自身 24h 延迟基线的滚动统计），auto 顺延 **B3**。完整白话版规则（含实例走查）见 2026-07-29 devlog。

## 4. 新增护栏：auto 命令过期哨兵

auto 档引擎周期内检查自己创建的渠道命令：**存在到期未执行的 → 立即暂停该站点 auto（回落 confirm）并产出告警**（复用告警/通知链路）。覆盖"命令发给不能执行的机器而静默卡死"的场景，零新机制（命令过期状态现成）。人工重新开启 auto 前应排查控制机配置。

## 5. 批次拆分

| 批次 | 内容 | 对应 v2.1 原稿 |
|---|---|---|
| **v2.9-B1** | Web 调权中心（按站点：模式三选一/策略表单/建议流水+证据+事后徽标/命中率报表卡）+ confirm 采纳链路（采纳→既有渠道命令,确认框,审计）——对评估逻辑透明,与 B2 正交 | v2.1-B2 |
| **v2.9-B2** | 引擎评估重写为模型组内比较（§3,纯 server 侧;observe 命中率重新积累） | 新增 |
| **v2.9-B3** | auto 执行器 + 全部护栏（含 §2.3、§4）+ before/after 记录与一键回滚 | v2.1-B3 |

**节奏纪律（沿用原稿）**：B1/B2 部署后以**新引擎**的命中率报表为准（判据：持续 ≥85% 且无最小可用集险情）；confirm 档用一阵体感核对；数据与体感都过关才开 auto。

## 6. 明确不做

agent 控制能力心跳上报（记为可能项）；跨站点联动调权；评分型质量模型（维持阈值型可解释规则）；探测数据并入（v1.1 探测批次仍挂起，落地后再议）。
