# RPM/TPM 覆盖时间窗口修正

## 原因与口径

Agent 约 30 秒采集一次，而 Server 原来以当前时刻查询最近 60 秒。
两次上报之间，窗口前部不断过期，窗口尾部尚未上报，会将延迟误表现为负载降低。

现在取所有必需日志采集实例最新覆盖标记的最小值 T，查询 `[T-60秒, T)`。
覆盖标记所在秒可能只采集了一部分，因此不计入窗口。没有新标记时窗口保持不变；
任一必需来源超过 90 秒没有覆盖，仍返回不可用，不将缺数据当零。
页面与调权引擎共用该口径。API 返回真实 as_of、window_start、delay_seconds，
页面显示区间和延迟。该值是已覆盖窗口负载，不保证与 NewAPI 当前时刻的窗口一致。

## 验证与部署

- 本地 MySQL 集成测试：固定延迟下完整 60 秒计数、轮询间稳定、新标记推进、
  左闭右开边界、多来源最慢标记对齐、缺失/过期来源保护。
- Dashboard/API 和调权引擎回归测试通过；前端类型检查及生产构建通过。
- 只改 Server 与前端，无数据库迁移；Agent rc94 可继续使用。
- 不增加 NewAPI 查询，不修改采集频率，不用倍率估算填补未上报的数据。
