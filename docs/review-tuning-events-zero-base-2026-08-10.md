## 改动全景

1. **零基础权重排除熔断状态机（b082033，唯一引擎改动）**：base_weight≤0 的渠道在混布保险丝之后、错误折叠之前直接短路——Phase 强制 normal、倍率 1、计算权重 0、熔断/探针字段全清零后落库跳过本轮。根治"恢复到权重 0"噪音事件（零权重渠道曾能走完 熔断→被动探针→circuit_recovered 权重 0 的全程）。新增测试：observe 熔断态+零基础权重+探针满额，断言回 normal、探针清零、零建议/探针/写入。
2. **变更记录页时间线→表格**（886c830..1794f61 十笔迭代）：模型/事件类型/渠道名或 ID 三筛选+客户端分页（20/50/100），列=时间/模型/渠道(含 ID)/事件签(熔断红)/权重变化/模式；筛选或切模型时页码归 1；历史遗留的"恢复到 0"事件被 validEvent 过滤（circuit_recovered 须 proposed_weight>0），7 天统计卡同口径。
3. **评估系数悬浮解释（833eff2）**：hover 因子行弹出四因子逐项算式，用落库证据字段（判据 v2 的 040 列）前端复算展示。

## 核验

- **前端复算公式与引擎逐项对齐**：速度 R=50/30/20 加权 TTFT 比、(1/R)^(0.35×灵敏度) 钳 [0.75,1.25]；缓存 比值^(0.15×灵敏度) 钳 [0.9,1.1]；输出 比值^(0.25×灵敏度) 钳 [0.8,min(1.2,cap)]；错误分段映射 1/5/15/30%→1/0.85/0.5/0.2；回退文案的证据门槛（1 万 prompt tokens/100 输出 tokens/基线 ≥2 合格渠道）与引擎常量逐一核对一致。
- **守卫跳过 foldErrorDecay 无积压风险**：折叠查询窗口钳在 max(now−15min, 游标)，零权重期间游标停滞不会在权重恢复后一次性折叠陈旧桶；KError/SmoothedErrorRate 保留不清零，错误记忆延续。
- 守卫位于混布保险丝之后（多模型渠道仍优先安全暂停）、写入逻辑之前（auto 不会因此写 0 权重到 newapi）；基线中位数计算不受影响（零权重渠道仍照旧贡献指标，行为无变化）。
- evidence.model 事件字段实存（continuousEvent 全事件带 model），表格模型列可靠；无 model 的 v1 遗留事件回退按 channel_id 查 bases 首行（可能取错模型，仅影响遗留数据显示）。

## 记档（P3）

- **悬浮解释不感知 off 模式/安全暂停**：模型关闭或 mixed_channel 暂停的行因子恒 1，但解释弹层仍按指标复算出"应然值"，与显示的 1.000 不符（仅这两类行、显示层）。
- **变更记录客户端上限 300 条**：筛选+分页观感像全量历史，实际只覆盖最近 300 条事件；7 天统计卡超 300 后少计。既有上限非本批引入，但新界面放大了误导面——后续可服务端分页。
- **切换每页条数不重置页码**：大页码下调页容量可能落在越界空页（点页码即恢复），归 1 监听可顺带加 eventPageSize。
