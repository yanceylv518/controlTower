## 跟进（1936e35,同日,验收通过零缺陷）

errorclass 提码正则补蛇形形态 `status_code[=: ]+(\d{3})`——生产 newapi 错误摘要实为该形态,既有"status code 空格"与"statusCode 驼峰"两模式均不匹配,状态码提取失败导致用户错误码集(含刚加的 424)整体失效、错误一直计给渠道。测试改用生产真实样本钉住三处(提码/聚合归因/告警排除)。**此修复解释了为何此前用户错误归因可能一直未生效,重要性高于体量;需随 agent 升级生效**。
