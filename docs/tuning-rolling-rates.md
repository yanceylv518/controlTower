# 调权中心滚动负载

- Agent 保持原有 30 秒采集周期；复用已读取日志，每秒、每渠道汇总消费日志的请求数和输入加输出 Token。没有新增 NewAPI 查询。
- `channel_rate_second` 为上报批次内的专用传输维度，服务端分流至 `channel_rate_seconds`，不写入普通分钟指标或五分钟汇总。计数与原指标使用同一个 metric batch 去重事务。
- 页面独立每 5 秒请求 `continuous-states?rates_only=1`，读取 `(当前时间 - 60 秒, 当前时间]` 的已上报数据；不等待完整分钟或调权评估。无新流量时自然衰减为零。
- 渠道 0 是 Agent 覆盖标记。站点内启用实例缺少 90 秒内的标记时，接口返回不可用；配置容量上限的渠道暂停上调，而非把缺数据当作零负载。页面不回退显示 15 分钟均值。
- 先部署服务端及迁移 065，再升级 Agent，最后更新前端。旧 Agent 无秒级计数，实时区域会提示升级；采集周期不变。
- 秒桶短期保存，随上报按索引分批清理 10 分钟前的数据。首次上报后最近一分钟可能尚未收齐，需要约一个采集周期预热。长请求、源库落库延迟、采集积压不包含在常态约 0–35 秒的展示延迟估计中。
