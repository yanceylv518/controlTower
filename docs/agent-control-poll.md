# Agent 统一控制轮询

新版 Agent 在主进程中共享一个控制请求调度器，归档托管控制和容器日志任务统一发送至 `POST /api/agent/control/poll`。每秒检查待发送队列，只发送已经到期的请求；同一窗口内的两类请求压缩合并为一次 HTTP 请求。无待发送请求时不访问 CT。两项到期时间不同或正在执行时，请求可以只包含一个部分，因此不保证每次都合并两项。

各任务仍独立执行并保持原有轮询频率、游标、授权、结果确认和失败重试语义。容器日志结果只有所属部分返回成功才清除，归档在所属部分返回的有效授权期间串行运行批次，剩余授权须覆盖 45 秒批次超时；控制失败后不再启动新批次。每次请求只携带尚待确认的快照，不重放缓存的任务领取结果。合并等待最多约 1 秒，远程请求超时 10 秒；任务执行期间不会阻塞其他任务提交控制请求，但共用网络请求失败会使本次包含的部分都重试。

CT 校验一次实例专用 Token，分别执行两部分的参数校验与事务，返回独立状态码和结果。一个部分失败不覆盖另一个部分成功的确认。归档写 RDS、容器日志本地读取、监控采集和数据上传没有合并；此改动减少重叠的 HTTP 请求和身份校验，不消除任务自身的数据库读写。

发布顺序：先升级 CT Server，再升级 Agent。旧版两个轮询接口保留，兼容旧版 Agent。新版不会自动回退旧接口，避免响应丢失后重复领取任务；连接旧 CT 时控制功能会报错等待升级。无数据库迁移或新增配置项。

归档执行已与控制轮询分开，批次间隔支持最低 2 秒（每批结束后计时），控制仍约每 15 秒轮询。日进度先持久化再上报，CT 明确确认后才清除对应快照，避免控制请求期间产生的新进度被旧确认覆盖。
