- 监控指定站点的测试账户或测试 Key，开始调用时提醒运营。

## 方案建议

- 监控分析下新增独立的“测试跟进”，与客户监控并列，提供测试名单：站点、站点通知显示名称、账户或 Key、客户备注、触发条件、运营接听号码、群通知渠道、启用状态。账户模式覆盖其所有 Key，Key 模式精确匹配指定 Key；身份使用站点与数字 ID，不保存完整密钥。
- 建议本轮首次出现调用日志就提醒一次，成功与失败均可触发，不设 Token 或消费门槛；连续调用不重复提醒。再次开始规则作为可选扩展，暂停恢复不隐式重置，显式重新监控才开启新轮次。
- 从启用边界观察，不因历史记录触发；处理迟到落库、并发提交及重启。调用日志时间与检测时间分别展示，不承诺请求刚发出时发现；未记录或无法归属身份的请求不可检测。
- 首版候选路线为 Server 读取站点真实日志库并集中增量匹配名单；实施前核验业务库/独立日志库选路、索引和完整性。缺少可用只读日志连接的站点需另行扩展 Agent 的专用活动事件上报，不能使用抽样日志代替。
- 首次命中产生独立事件及拨号任务，按监控轮次去重；账户和 Key 重叠时向同一接听人合并。检测、通知结果和运营已关注状态独立保存。
- 电话为主要提醒，群消息可同步提供调用详情。按用户最新要求，统一维护运营人员列表，每个测试对象可多选通知人，分别通知选中且启用的人员；未接听自动重拨或升级备用人需接入最终通话回执后再设计。
- 两类电话共享同号码全局频控，业务事件身份独立。频控阻止外呼时明确展示原因并保留消息；若排队补拨，须设有效期及过期状态，避免过时提醒。
- 区分请求已受理、拒绝和结果未知；未知不自动重拨，不将已受理记为已接听或已关注。

## 站点通知显示名称（2026-09-20 补充）

- 用户明确要求：配置测试监控时，给对应站点配置一个用于消息展示的名字。
- 建议字段名为“通知显示名称”，在选择站点后展示并允许编辑；说明为“用于测试调用提醒的电话播报和消息展示”。示例：站点原名 `site-a`，通知显示名称“华东测试站”。
- 建议在测试监控模块内按站点保存，同站点的账户及 Key 监控共用该名称；编辑已有名称时提示影响该站点全部测试提醒。该配置不扩展到其他类型告警。
- 电话模板 `${site}`、群消息站点名称及事件详情统一使用该显示名称。建议留空时沿用站点原名称，界面预览最终名称；可填写简短、适合语音播报的中文名称。
- 站点选择、监控身份、权限、去重和路由继续使用原站点 ID；名称只是展示配置。同名站点不能因此合并，配置页同时展示原站点名称以便识别。
- 建议事件生成时保存显示名称快照，后续改名用于新事件，历史记录及同一事件的重试保持原文案。后续验收覆盖切换站点隔离、空值回退、电话和消息一致、改名及重试。

- 尚未提交阿里云，尚无模板 ID。新模板需审核，接入时参数须对应新模板，不能沿用 TPM 模板的 customer + direction 参数内容。
- 若“真实号码”指现有阿里云专属外呼号码，按同账号内复用该号码或已绑定号码的服务实例设计，新模板选择专属模式；须确认号码正常及业务场景适用。无需因新增模板单独购买号码。若指运营接听手机号，也可继续使用，拨号额度共享。
