## 追加式归档校验（2026-09-21）

- 目标：用户确认源日志默认不UPDATE、继续只读查询源表，并授权实现“源读取一批→目标回读校验→原子提交”，日终收尾一次，取消默认四轮核验及周期历史复扫。本节优先于下方此前阶段结论。
- 责任/范围：当前 Codex 会话，main / 23468bae 混合工作区；新增 Agent copy_evidence 与 022_scan_evidence，修改日期扫描/工作流、核验方法契约和页面说明；未调用子代理，其他修改保留，未提交/发布/部署。
- 实现：既有 writer 会回读校验所有传入行（含一致跳过写入的行）。本轮在同一目标事务加入源有序完整摘要/逐行hash、来源证据游标及完成标记，原始日志/统计/证据/checkpoint/receipt原子提交。逐行hash复用archive_reconcile_issues，run在日终创建后才成为可见核验记录；022保存task/attempt到run绑定、scan_json、last_batch_id、completed及更新时间。
- 日终：已结束历史日期补齐一次后，copied_source_paged只读取归档库，对捕获源证据逐ID比对并使用既有revision/lease/assurance及封存门禁。NULL/原始全字段/精确大整数均参与摘要；少、多、不同均受阻。方法明确区别于旧stable_window_paged，内部target_second沿用存储槽编号，不代表两次扫描。旧独立强核验接口保持兼容，但默认全量任务不调用。
- 当天/升级：仍按时间游标采集当天；结束且超过delay后，新建一次从日初开始的收尾补齐，捕获游标之前的迟到INSERT。之后归档库核对封存。旧未完成日期任务无来源证据则重扫该日期，不以归档数据补造来源证明；旧封存构建继续恢复。取消近期7天定时复扫；目标revision变化、受阻重试仍可调度补齐。
