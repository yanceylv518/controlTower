# 使用日志 Fallback 请求链路

- 标识：2026-09-18-fallback-request-chain
- 更新时间：2026-09-18 08:28 +08:00
- 状态：待页面验收
- 目标与验收条件：按用户确认设计，复用现有黄色 fallback 图标，点击后在当前行下查看关联尝试，支持只看该请求；保留列表与 NewAPI 一致的倒序。
- 负责会话、分支和修改范围：当前会话，main；ReadonlyLogsView、FallbackRequestChain 组件、fallbackRequestChain 工具和前端回归。
- 实际结果与关键决策：使用现有 passthrough.logs 接口按站点、请求 ID 和用户 ID 查询，不附加列表渠道/模型/类型等过滤；连续拉取关联分页，不仅关联当前页。保留原图标，悬停显示原始渠道序列及次数，点击展开、再次点击或 Escape 收起。桌面 colspan 跟随可见列，移动端在卡片内展开。支持单条详情、刷新、只看此请求和清除关联筛选。
- 排序与边界：优先用 other.admin_info.use_channel / use_channel 原始顺序，保留同渠道重复尝试；只有对应位置可信时排列尝试，冲突或未确定位置的日志单独展示。没有可信序列时明确标注按时间及 ID 排序。缺失尝试仅显示渠道占位，不编造错误、耗时或成功结果；消费日志标注消费，退款独立列出。日志耗时可能累计，不标为单次耗时。
- 查询限制：以当前记录前后至少一天为窗口；前向回溯结合 use_time 扩展，最多前 30 天后 1 天，符合现有接口 31 天限制；界面显示范围，不宣称全历史完整。最多查询 1000 条，截断、缺失当前记录或缺少预期渠道日志时提示。新日志可能继续写入，可刷新链路。
- 权限与隔离：仅管理员展开，viewer 原有权限与后端脱敏不变；按同请求/同用户二次校验返回项，关闭、切换行/站点/页码时取消旧请求。缺少身份不发广泛查询，查不到不按用户名或时间猜测。
- 验证：新增工具/筛选行为测试共 13 项，覆盖延迟写入、重复渠道、跨页去重、缺失/冲突、退款、取消、上限、身份过滤和只看请求时清除冲突筛选。全量 165 项先通过；补充 1 项后最终相关 40 项通过。最终 pnpm typecheck、pnpm build 通过，构建仅有既有大包提示；git diff --check 通过。本地 Vite 已收到热更新。
