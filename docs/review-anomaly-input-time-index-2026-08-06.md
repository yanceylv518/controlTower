## 61e3bc8 异常判定改用扣缓存前的原始输入

缓存语义改造（c998218）引入的跟进修正：openai 形态"输入全命中缓存"的请求归一化后 PromptTokens=0，会被误判 `input_token_zero` 落异常单、不进账单。修正：PagedLogRecord 增 `SourcePromptTokens`（扣减前按值拷贝，时序核过），anomalyReasons 与异常单落库均用原始值；全缓存请求回归正常计费路径（输入泳道 0 + 缓存泳道×缓存价），有测试钉住。判档（SelectPrice/ContextTokens）与参考金额口径不变。

- 记档：本修正改变异常归类（少判），request_key 仍为 v4——**生产（rc26）从未部署过 v4，无需再升版**；但若有环境已部署 rc29 并生成过账单，需强制重新生成才能吸收本修正（rc29 未部署则无此事）。

## 012235f 列表查询对齐时间索引（选路设计阶段 A）

- 列表查询：`BETWEEN` → 半开 `created_at>=? AND created_at<?`；排序 `id DESC` → `created_at DESC,id DESC`，与 `idx_created_at_id` 完全对齐——优化器失去选主键倒扫赌局的理由（设计文档 §1 的病根）；count 原始回落路径同步改半开；
- **闭环 rc28 验收记录的 P3**：列表/统计/聚合三路径区间端点自此全线半开一致，end 整秒行为统一；
- SQL 形态有源码文本契约测试（禁 BETWEEN、排序串精确断言）；limit+1/has_more 不受波及；排序变化对用户不可见（id 与时间同序，翻页在 (created_at,id) 全序上稳定）；
- 未加 FORCE INDEX：可接受（排序+范围双对齐后优化器应自选时间索引），**部署后 EXPLAIN 实证仍必做**——设计文档 §7.1 的三路径对比里，本基线即路径②，请以生产计划确认 `key=idx_created_at_id`、`Extra` 无 filesort；
- 流程记档：阶段 A 属设计文档"建议实施顺序"内容，但**开工令未发**，codex 自主实施——改动低风险且与共识方向一致，按验收放行；阶段 B（应用层选路）仍待评审问题全闭环 + 开工令。
