# 调权中心渠道即时同步

2026-09-05

## 行为

- 进入调权中心、刷新浏览器或点击“刷新渠道信息”，主动读取 new-api 最新渠道。页面加载与该读取并行，不等待直连返回；读取完成后合并进页面（并通过变更通知再次校准）。原有 Agent 默认 600 秒渠道采集周期保留。
- 未配置直连的站点（仅由 Agent 指令管理）是合法配置：自动刷新静默跳过，沿用 Agent 采集快照；只有点击“刷新渠道信息”时提示“未配置直连”。“初始化/刷新基础值”在这类站点直接使用 Agent 快照。
- 刷新渠道信息保留已有基础权重、基础优先级和容量设置；页面手动刷新保留尚未保存的编辑。原“初始化/刷新基础值”仍是显式覆盖基础值的独立操作，但先获取最新渠道信息。
- Server 直连调权成功后立即将实际写入字段回写 `channel_current`；Agent 命令只在收到成功回执后回写。待执行、失败命令不提前显示目标值。已确认的写入无条件应用（不受 Agent 时钟偏快导致的“未来” captured_at 影响），captured_at 只向前推进。
- 页面通过可取消的长轮询接收已持久化变更通知，立即读取新状态；不等待手动刷新、30 秒运行时轮询或 10 分钟快照。保存自己的修改时由保存响应和后续加载更新。
- 删除仅沿用既有采集实例快照同步范围，不扩展为所有实例清理。
- 晚到的旧快照不能覆盖更晚的已确认值；旧全量快照也不能删除更新的渠道行和对应基础值。多实例相同时间戳查询按实例 ID 去重。

## 接口与升级

- `POST /api/dashboard/tuning/channels/refresh?site_id=...`：Server 直连分页获取渠道；未配置直连返回 409 `direct_control_not_configured`（页面据此静默），不回退到 Agent。直连失败返回 502 并明确提示，旧缓存不会被当作同步成功。
- `GET /api/dashboard/tuning/channels/changes?site_id=...&after=...`：最长 25 秒的变更通知等待，随后自动重连。通知按站点分发、在当前 Server 进程内广播（多进程部署跨进程不通知）；保留原周期读取作为兜底。
- 发布只需更新 Server 和前端，无新增 Agent 刷新命令。原有 Agent 定期采集和成功 `channel.update` 回执保留。
- 新增 `067_tuning_rule_length.sql`：`tuning_recommendations.rule` 从 16 扩到 64 字符，修复 18 字符的 `base_priority_sync` 无法落库的问题。没有在本次工作中部署生产环境。

## 验证

- 渠道列表分页、缺失字段/不完整分页拒绝、页面通知唤醒的单元测试。
- 独立本机 MySQL 验证优先级即时回写、失败命令不回写、权重与优先级成功回执、基础值保留、旧快照及旧空快照保护、多实例去重和后续外部修改覆盖。
- 相关 Go 包回归测试及前端类型检查、生产构建。
