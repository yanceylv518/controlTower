# 使用日志请求链路

用户于 2026-09-18 确认：保留现有黄色 Connection 图标作为唯一入口，展开行内链路，不增加“重试 N 次”文字按钮。

## 显示

主列表维持 created_at DESC、id DESC。链路头部展示请求 ID、排序依据、只看此请求和收起；卡片展示序号、渠道、日志类型、记录时间、日志耗时、错误摘要或消费金额。当前记录高亮，每条可打开原日志详情。原始耗时可能累计，不拆分推算单次耗时。

原始渠道尝试序列保留重复项。各日志的序列前缀和渠道共同确定位置；没有前缀时仅唯一渠道能直接定位。无法定位、重复占位或冲突记录不强行拼接。缺失位置显示“缺少日志”。没有可信序列时按日志时间/ID 正序并明确不代表实际执行顺序。退款等日志不计为一次重试。

## 查询

复用现有只读列表接口，必须限定当前站点、非空请求 ID、当前用户 ID；移除模型、渠道、类型等列表过滤。独立范围至少包含当前记录前后一天，较长 use_time 可向前扩展至 30 天，上限 31 天。每页 100 条、最多 1000 条，逐页读取、按日志 ID 去重；界面展示查询范围及缺失/截断情况，不承诺已归档或范围之外的日志可用。

只看此请求使用同一查询范围和身份条件，清除冲突筛选并回到第一页，统计和总数同步过滤；原主列表依旧倒序。页面展示关联用户筛选状态，可用清除入口恢复默认条件。

仅管理员可展开。关闭或切换站点、日志、分页时取消请求，过期响应不能覆盖新链路。空请求 ID 不用用户名、模型或接近时间替代关联。敏感字段隐藏偏好同步作用于请求 ID、错误内容和金额。
