# 归档四任务与每日流水线

> 2026-09-22：后续重构采用[两任务归档与多维日统计方案](archive-two-task-daily-rollup-design.md)。下文保留四任务实现背景，不作为新方案的业务规则；新方案尚未完成代码迁移。

实现状态：本地已接入 Agent 数据库执行器、Server 能力门禁与配置、四任务卡和每日状态。新能力为 `archive_four_tasks_v1`，显式配置 `pipeline` 后才运行四任务；没有该配置继续兼容旧 `WorkflowPass`。尚未发布或部署到远程，不能将本地验证视为线上已升级。

## 最终业务规则

1. **版本迁移**：准备结构、清理旧统计台账、提交迁移完成标记。到这里结束，不包含历史整理。每个需迁移的版本只执行一次，重启续跑，不重复清理；原始月表不清空。
2. **历史整理**：按日期读取已有归档月表，重建贡献台账和日/月统计。整理一天结束就交给任务 3，不先整理完整个历史。
3. **校验与封存**：针对整理完的日期，对照源数据补齐、核验、封存，持久化本轮成功或具体受阻原因，再处理下一天。日期级问题不阻塞其他日期；数据库断连等全局故障不能伪装成每天失败。
4. **日志采集**：独立源读取游标，将日志写入 `logs_YYYYMM`。结构就绪后可与任务 1 的旧台账清理、任务 2 的整理并行。与任务 3 整体互斥，包括任务 3 的归档库核验、封存阶段；不再沿用仅源查询期间互斥的早期方案。

任务 2、3 串行，按“整理日期 A → 核验封存日期 A → 记录结果 → 整理日期 B”交替。独立暂停保留依赖关系；暂停校验不能把该日视为校验完成。

每轮按站点时区固定截止日期为昨天；跨午夜不延长本轮。例如 9 月 22 日启动，本轮最多处理到 9 月 21 日。

## 每日采集完成

用户确认使用后续日期已有已提交原始记录作为本轮采集跨过该日期的信号，包括下个月月表有实际数据。只有表名存在、空表、源查询读到但尚未提交的行都不构成信号。

这不是永不补写的完整性保证，不再额外强制等待所有迟到数据。没有后续日期记录时保持采集中或等待采集，不悄悄用当前时间或空查询认定完成。没有证据的空日期不能伪造成零行且已采集。

原始写入必须在同一事务内更新所影响日期的 revision，包含跨日、跨月迁移记录的旧日期和新日期。相同原始数据的幂等重放不推进 revision。

正常流转：采集完成 → 整理 → 校验与封存 → 结果。任何后续补写或修改，立即使原整理、校验和有效封存状态失效，标记数据更新并重新排队。旧封存版本本身不可变，继续保存供追溯；旧版本存在不代表当前版本有效。

## 调度核心与数据库接入边界

- `State.Reserve` 发放持久任务 token。任务 1/4、2/4 可共存；任务 3 独占执行，不与 2/4 重叠。
- `BeginRound` 固定截止日期。不能在仍有执行中任务时开启新轮次。
- `ObserveCommittedRows` 接受原始行所属日期与实际变动日期，维护采集边界并立即撤销旧结果。调用必须和原始写入一起提交，不能提前上报。
- `Finish` 比较 token 和精确日期 revision。整理期间采集补写同一天，旧整理结果必须回滚并重做；校验封存也不能发布旧 revision。
- 日期级失败形成带 revision 和轮次的结果，本轮可继续后续日期，新一轮可以重试。基础设施失败保留可恢复预约并等待重试，不给日期记成功或受阻结果。
- 独立暂停只阻止新预约；在途批次必须完成或回滚后才释放。不能在超时后直接解除互斥：必须先推进数据集 writer epoch，确认旧写入无法提交，再恢复预约。
- 编解码校验拒绝损坏或未知版本检查点，不能在解码失败时回退空状态重新迁移。

**该核心不是并发安全的内存锁。** 调用方必须在数据集 writer fence 下读取持久状态并锁定调度记录，检查身份、epoch、token，在同一数据库事务里完成原始行、对应台账、日期 revision 与相关检查点更新。事务失败必须丢弃内存副本。提交结果不确定时从持久回执恢复，不能仅依据心跳宣布成功。

## 已接入的持久化与升级路径

- 归档库迁移 023 `archive_raw_state` 保存原始记录指纹与原日期，024 `archive_pipeline` 保存四任务预约、每日修订、独立游标与诊断，025 `archive_pending_statistics` 记录跨日/跨月修正等待更新的统计贡献。原始写入、日期失效、队列和采集计数一起提交。
- 采集不写 `archive_log_state` 和日/月统计。整理使用已有贡献做幂等差量，能够接续 rc129 已整理部分，避免重复累计；原始月表不清空。旧流程仍在 reset 阶段时续清理，已进入 import_target 之后不重复清理。
- 持续采集沿用独立 incremental 回执游标。指定日期范围使用独立 scan 回执，支持范围内从旧到新或从新到旧，不改变持续采集游标；回到持续模式仍会扫描未提交的 ID，不将 MAX(id) 当检查点。
- 校验封存复用原有源证据、关联日期组和不可变版本发布。日期版本首先由原封存事务发布，调度记录随后根据持久结果收敛；崩溃后重读回执，不根据心跳虚构成功。该期间采集预约不能获得许可。
- 启用四任务前需暂停旧流程并等待确认；旧日期仍在补齐/核验/封存时拒绝切换。先完成该日期再暂停。启用后禁止移除 pipeline 回到旧写入路径。
- 先升级 Server，再升级 Agent。旧 Agent 不会得到四任务写授权。范围变更要求整体暂停并确认；四任务开关在当前批次结束后应用。
- 日期级受阻保存修订和原因后继续下一日；基础设施失败保留预约，至少等待 30 秒后重试。界面可重新排队受阻日期；不重做版本迁移。

## 数量、索引与操作观察

日历的 `raw.rows` 来自原始月表的独立索引计数，附实际统计时间；不使用整理中的 `log_daily_stats` 数量代替。Agent 每次最多统计一张月表，每张表缓存五分钟，查询有 2 秒服务端/2.5 秒客户端预算。失败时保留上次数量和原时间，并展示诊断。Server 存储这些摘要，浏览器只读取 Server API，刷新不会扫描源库。巨大月表可能超出计数预算，显示计数失败而非零；本轮没有生产规模性能验收。

迁移会给缺少日期访问索引的归档模板和月表逐表添加 `(created_at,id)` 在线索引。索引 DDL 使用独立连接及最长 30 分钟预算，避免普通 30 秒批次超时反复取消。每次启动新 DDL 都需新授权；已发起的非破坏性在线 DDL 可在暂停后完成，暂停仍阻止新的日志数据批次。Agent 关闭时取消本机 DDL。运行账户需要目标库 ALTER 权限；索引空间、I/O 与元数据锁成本需在生产观察。

每个任务保留具体表、日期、操作、批次时间、错误代码、MySQL 编号/SQLSTATE及可定位的日志 ID；不输出 SQL、凭据或日志正文。日历展示收集边界、迁移等待、整理、待校验、封存、受阻和数据变化，并解释各状态及后续流转。只报告最近观察，过期报告不视为仍在执行。

## 验收

- 整理与采集真实 SQL 可重叠；校验封存与采集源读取并发峰值不超过 1。
- 暂停、重启、失去授权、事务超时及提交结果不确定均不丢进度、不重复统计、不放行旧 worker。
- 月末、当天排除、跨午夜固定截止、缺少次日数据、迟到新增、内容修正、跨日迁移均有测试。
- 已封存后补写立即显示失效；核验封存中版本变化不能发布过期结果；旧封存记录保留。
- 每天整理后立即核验封存，日期错误记录后继续，全局故障等待恢复，不批量误报日期失败。
