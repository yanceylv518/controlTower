# 健康渠道动态配权（观察版）

## 目标

在固定阈值降级与恢复验证之外，对同一模型、同一优先级的健康渠道计算相对权重建议。当前版本只记录观察建议，不写入 new-api，也不启用主动探针。

## 参与条件

- 渠道已启用，且只承载一个模型。
- 渠道位于该模型当前最高可用优先级。
- 当前窗口请求数达到 `min_samples`。
- 渠道不处于降级或恢复验证状态。
- 同组至少有两个符合条件的渠道。

不满足条件的渠道不参与基线，也不生成动态配权建议。

## 指标口径

- TTFT：窗口内 `ttft_p95_ms`，转换为秒；缺失时回退到请求总延迟 P95。
- 错误率：`max(总错误数 - 用户侧错误数, 0) / 请求数`。
- 缓存命中率：`cache_tokens_total / cache_prompt_tokens`，只奖励高于组内基线的渠道。
- OTPS：`otps_output_tokens / otps_duration_seconds`，只作为小权重辅助指标，不视为容量。

组内基线均按请求数加权，避免低流量渠道对基线产生过大影响。

## 计算与保护

四个相对因子相乘得到原始倍率：

- TTFT 越低，因子越高。
- 服务端错误率越低，因子越高。
- 缓存命中率高于基线时获得有限正向奖励。
- OTPS 高于基线时获得有限正向影响。

随后依次执行：

1. 原始倍率限制在 `min_multiplier` 与 `max_multiplier` 之间。
2. 使用 `smoothing_alpha` 向原始倍率渐进靠拢。
3. 使用 `max_increase_per_round` 与 `max_decrease_per_round` 限制单轮变化。
4. 对当前权重乘以保护后倍率并四舍五入，最低权重为 1。

建议证据会保存每项指标、组内基线、各因子、原始倍率和保护后倍率，供调权中心复核。

## 与降级的关系

动态倍率只负责健康渠道之间的相对分配。错误率线、熔断线和延迟恶化标准仍负责异常渠道降级；恢复继续使用真实流量验证和指数退避，不使用动态倍率替代固定阈值。
