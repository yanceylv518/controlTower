# 账单与报表前端设计

2026-09-29，待人工确认。仅设计与会话交互草图，未修改业务前端或后端。

用户要求改为逐模块梳理，当前仅讨论用户账单。最新日/月展示、月下载三类统计、每日模型/令牌维度与空输出默认保留的要求见[用户账单专项](design-user-billing-2026-09-29.md)，优先于本文相关早期草案；前述交互草图未同步本次新要求，不视为最终页面。

## 最新澄清：报表与账单分开

用户纠正前一版混淆：上游的逐渠道调用、费用和折扣是报表需求，不据此合并上游账单和上游报表菜单。用户进一步要求用户报表展示每个用户的调用、费用及模型折扣。以下作为最新页面口径，优先于后文早期摘要：

- 菜单保持用户账单、上游账单、报表中心、生成记录、结算设置。报表中心内为用户报表/上游报表，两者再切日报/月报，不新增四个重复一级菜单。交互草图将用户报表/上游报表直接作为演示页签，不表示新增两个生产侧栏菜单。
- 用户报表：先按用户汇总调用次数、用量与费用；展开每日、模型明细，支持按用户、按模型及用户×模型查看。展示每个用户每个模型实际适用的折扣与生效日期。不同模型/用户折扣不能用一个简单平均折扣计算，汇总展示“多种折扣”，下钻看分项。
- 上游报表：选择上游后逐渠道展示每日调用、用量、折前费用、渠道折扣和折后费用；支持按渠道、按模型、渠道×模型查看和筛选。按模型汇总须先分别应用每个渠道当日折扣再相加，不套一个统一模型折扣。折扣变更按生效区间拆分。
- 折扣和费用口径：用户实际日志扣费如果已经应用模型/用户折扣，只展示历史证据，不再乘一次折扣。只有可靠折前金额和规则才能同时显示折前/折后；无法还原显示未知，不倒推补造。模型折扣具体来自NewAPI历史计价证据还是独立协议规则仍需确认，不能因为新报表字段而改变用户账单计费。
- 用户账单：默认每日列表直接展示请求数、各类Token、费用、来源和完整状态，每天提供“统计与明细”和“下载日账单”。可先选择用户，也可按用户分组查看日期；每日下载包含统计与该日全部请求明细，不限当前分页。
- 每日下载建议XLSX内含账单总览、模型统计、令牌统计、请求明细，统一对象/日期/来源/规则版本及金额口径。明细超过单文件承载范围时提供ZIP，包含统计工作簿和完整分卷明细，明确格式，不静默截断。异常/排除记录与纳入统计记录标识清楚，统计和明细可勾稽。
- 报表供分析，账单供核对和定稿，下载与状态保持区别；用户本轮未要求重构上游账单的既有页面结构，暂保留。

新版草图重点演示用户日账单、用户报表及上游报表三个场景。示例折扣不是已确认结算规则；仅通过脚本语法检查，未浏览器验收或接入真实数据。

## 菜单与入口

现有账单管理升级为“账单与报表”，五个菜单：

| 菜单 | 页面内容 | 建议路由 |
| --- | --- | --- |
| 用户账单 | 用户应收，日账单/月账单切换 | 保留 /billing |
| 上游账单 | 上游应付，日账单/月账单切换 | 保留 /billing/channels |
| 报表中心 | 日报表/月报表，用户/上游视角 | 新增 /billing/reports |
| 生成记录 | 每日自动、手动补齐、月结和重算的记录与进度 | 保留 /billing/tasks，改显示名称 |
| 结算设置 | 自动生成、上游与渠道、结算规则 | 新增 /billing/settings |

渠道折扣收进结算规则，上游管理收进上游与渠道；旧地址重定向到对应页签，并保留原权限校验。账单核对通过详情待确认项及列表状态筛选进入，原核对地址继续兼容。现有用量统计保留实时监控用途，不在本轮直接删除或替换。

不分别增加用户日报、用户月报、上游日报、上游月报四个侧栏菜单，以页面内视角和周期切换承载。站点使用现有全局选择器，不再页面内重复一个站点下拉。

## 用户/上游账单页面

共同结构：页面标题和生成按钮 → 日账单/月账单切换与日期 → 金额/对象数/缺口摘要 → 数据覆盖提示 → 对象列表。生成入口始终可发现；是否可提交由权限、选中来源和配置决定。

日账单默认当天以前的最近账单日，可选单日或查看月内每日记录；月账单默认本月预估，切历史月份查看正式版本。草图为展示缺口使用固定9月示例，生产日期控件需覆盖这些模式。

用户列表按用户归组，展开日期结果；上游列表按上游归组，展开日期结果。多日概览可一行汇总对象金额与缺口，详情落到具体日期。不能把“一个对象的一行”误当作“一天一个全站完成标志”。

列表关键列：对象、日期/账期、应收或应付金额（币种）、来源、数据状态、账单状态、操作。已有日结果来源不同则显示“多来源”并可下钻，不能在总览强行统一标为当前默认来源。每个单独账单版本仍只有一个来源。

详情桌面采用右侧抽屉，宽度适应可用空间；包含汇总、明细、核对、版本记录。用户下钻令牌/日期/模型，上游下钻渠道/日期/模型；大量请求明细按需分页，不默认加载整月。查看明细、下载与复核各自受权限约束。草图使用内联展开以方便在会话中浏览，非最终抽屉实现。

## 生成与补齐交互

1. 点击生成，打开桌面抽屉/手机全屏面板。当前用户页默认用户，当前上游页默认上游；可改为两者。草图默认两者展示独立缺口。范围为全部配置对象或明确所选对象，不把当前搜索结果隐式当全部对象。
2. 选择源库/归档库，显示保存的开始日期至昨天、时区与对象范围。账单表格当前浏览月份不悄悄缩小补齐范围；如需仅重做一个区间使用独立重算入口。
3. 自动只读检查缺口，显示正在检查；支持重新检查。分别列出用户与上游的已完成、在途、待补和受阻数量。草图为方便演示采用“检查缺失日期”按钮。
4. 缺口不为空时显示“补齐 N 项”，同时注明涉及多少日期和对象；日期数与任务数分开。检查结果变化、切站/改来源/改对象都使旧检查失效。全部完整则显示“已更新至昨日”，无新增任务；已有在途则提供查看进度。
5. 提交后按钮防重、后端复核；接收成功显示持续进度条及生成记录入口，可关闭面板继续后台执行，不阻塞看旧账单。
6. 归档未就绪时展示具体日期及原因；允许处理可用日期，其余进入等待。明确更换源库须用户重新选择并检查，不自动切换。
7. 完成按对象和日期增量刷新，保留筛选/滚动位置。仅缺口全部消除才宣称已补齐；部分失败显示“完成X项，Y项待处理”，可只重试失败项。

## 报表中心

日报/月报与用户/上游视角为两个独立切换控件。日报默认昨日，月报默认本月截至昨日，明确区间和截止时间。可按对象、模型过滤，支持明细与导出。

顶部请求数、Token与用量金额；中部小时/每日趋势；下部用户或上游排名及模型构成。应付折扣金额若显示，另列为“应付预估”，不把上游关联渠道的日志金额直接命名供应商成本。不在成本规则未确认时显示毛利。

共用读取、日汇总、覆盖与补齐机制，不共用定稿状态。报表数据可更新，已定稿账单固定；报表带来源、覆盖与导出时间，差异可追溯。源库与归档结果不可叠加计数；基于所选有效版本汇总，历史来源混合时明确逐日来源。

## 生成记录与设置

生成记录以批次为行，显示触发方式、维度、来源、范围、完成/待补/受阻数及最近更新。展开查看用户和上游独立子任务。批次条数不等同账单数量；无总量证据不画虚假百分比或预计时间。

设置三页签：自动生成（开关、两类对象范围、开始日期、来源、每天时间、月结安排）、上游与渠道（归属及生效期、未归属渠道）、结算规则（折扣、币种、零输出、复核策略）。配置保存明确未来生效，旧版本不回写。手工补齐继承默认配置，但每次来源可选。

## 页面响应与异常状态

| 场景 | 页面行为 |
| --- | --- |
| 首次加载 | 局部骨架屏，不把未知金额和未知缺口显示0 |
| 刷新失败 | 保留旧数据并显示更新时间与失败提示，提供重试 |
| 切换站点/对象/来源 | 取消旧请求，清空不相容数据；旧响应不得覆盖新页面 |
| 尚未配置来源 | 保留生成入口，打开后引导配置；账单历史仍可读取 |
| 数据不完整 | 金额标部分/预估，常驻缺口入口，禁止定稿 |
| 读取成功且确无用量 | 显示0用量完成，与未生成明确区别 |
| 任务运行中 | 可看旧结果，进度增量更新，不全屏锁住页面 |
| 没有权限 | 隐藏不可用操作并服务端拒绝；直接访问有明确无权限页 |

当前 AppShell 将整个账单组绑定源库只读连接的门槛需重设计：看历史账单不依赖实时来源在线，选择归档路径不要求源库日志连接，币种/规则等依赖独立提示。菜单显隐、路由、服务端的账单/归档/报表权限必须一致，不能通过复用归档管理员接口扩大报表查看权限。保留现有 viewer 范围，是否新增客户自助账单权限另行确认。

## 响应式布局

- 桌面大于1200px：沿用应用侧栏与顶栏，筛选/操作同行，三项摘要一行，宽表格和详情抽屉。
- 901–1200px：减少次要列和固定列，筛选允许两行，表格仅必要时局部横向滚动，不产生整页横向溢出。
- 900px及以下：接入现有手机导航，从更多进入账单与报表；页面内日/月切换保留，筛选收进面板；列表为卡片，常显对象、金额、来源、状态和查看。生成与详情使用全屏面板，滚动内容和安全区内操作栏分离。
- 窄屏金额和状态不依赖悬停，长名称换行；图表减少刻度，列表按需加载，搜索/来源改变重置游标。保留已有桌面紧凑视觉，不引入全局样式改造。
- 键盘可操作，面板焦点管理及关闭后返回触发按钮，错误文本配合颜色，数字对齐并保留币种。草图随嵌入容器720px转为单列，不等同项目生产900px断点。
