# 日报表设计（待评审）

## 用户下按模型分项（用户新增要求）

用户维度直接显示用户汇总行和各模型分项，包含模型折扣、请求/失败、用量、实际收入、上游成本及毛利。模型分项也可展开其上游成本，避免仅展示全用户平均值。折扣展示应来自请求历史证据，不以收入/上游折前成本倒推；已折扣的实际quota不再乘折扣。

同一用户模型在所选日期存在多种历史折扣时显示“多种折扣”及分项值，不能简单平均；用户汇总行折扣显示不适用。草图用显式虚构折扣0.95/0.92等演示，模型A的9.8/9.6折示例代表同日不同历史规则，费用合计不变。

用户要求每日系统统计，分用户、模型、渠道展示，并关联上游成本。本轮设计不包含月报，不修改业务代码。

## 页面

沿用紧凑外观，日期选择后展示全站请求总数/成功失败、用户收入、上游成本、毛利及毛利率。用量行显示普通输入、输出、缓存读/写及空输出数量。示例中成功请求为消费记录，空输出属于消费请求子集，不重复记为失败。

明细切换按用户、按模型、按渠道；各维度都是同一批请求的不同分组，分别可对齐全站统计，不互相相加。各行显示请求/失败、用量、收入、成本、毛利及毛利率。按渠道还展示上游和模型；真实多模型渠道应显示模型集合，分组按请求实际模型。

每行“成本明细”行内展开上游、渠道、模型、计费请求、折前费用、渠道折扣和成本。从用户或模型维度也能追溯其使用的各上游渠道成本。无需跳到账单页面。

## 金额关联

- 收入：用户实际quota按配置换算，已包含用户模型折扣，不重复折扣。
- 成本：同批请求的other.quota_before_discount换算折前费用，按所属渠道当时有效折扣计算后汇总。
- 毛利＝收入－上游成本；毛利率＝毛利÷收入，收入0时显示不适用。这里只是请求收入与上游成本差额，不等于净利润。
- 通过请求关联用户、实际模型、渠道以及当期上游归属。历史日期按归属与折扣生效区间匹配，不拿当前关系重写历史。
- 缺少折前额度、渠道归属或折扣时，相关成本标待核算，不能当0，也不能把部分成本显示为完整毛利；需列出受影响请求。当前首稿使用全部匹配的示例状态，待核算交互待继续设计。
- 报表复用统一用量和计价事实，不要求先生成账单；报表更新状态与账单快照独立。币种/额度换算按配置，跨币种不能直接合计。
