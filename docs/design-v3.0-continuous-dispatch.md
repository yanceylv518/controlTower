# 设计 v3.0：连续配权调度（基础值锚点 + 熔断探针）

日期：2026-08-01。来源：用户提供的外部方案总结（ChatGLM 对话），经对照评审后用户拍板采纳为 v3.0 调度引擎，**替换 v2.9 的值班降级/试岗模型**。对照分析与取舍见 §8。

## 1. 核心模型

```
W_realtime = W_base × M          M = K_speed × K_cache × K_otps × K_error（上限 clamp 1.5，下行不设限——由 K_error 驱动至熔断线）
W_realtime 四舍五入，非熔断态最低 1；基础值 W_base 与基础优先级由 CT 配置界面持有。
```

**基准**：按模型分组，取正常态（非熔断、启用、单模型）渠道最近评估窗口指标的**算术平均**：AvgTTFT_P50/P90/P95、AvgCache、AvgOTPS。组内正常渠道 <2 → 该模型不调权（全部保持基础值）。

**因子**（λ=敏感度，默认 1.0，站点级可配）：

- `K_speed = (1/R)^(0.5λ)`，R = 0.5×(TTFT_P50/Avg) + 0.3×(TTFT_P90/Avg) + 0.2×(TTFT_P95/Avg)。**偏离原方案记录**：用 TTFT 三元组而非总延迟（use_time 无 P90 指标，且首字延迟更贴调度语义）；
- `K_cache = (Cache/AvgCache)^(0.5λ)`；
- `K_otps = (OTPS/AvgOTPS)^(0.5λ)`，硬上限 1.5；
- `K_error`：**持续状态**（非窗口量），按分钟桶增量更新 `K ×= 0.8^渠道侧错误数 × 1.08^成功数`，范围 [0.001, 1.0]，新渠道初始 1.0，状态入表、重启恢复。**偏离原方案记录**：渠道侧错误用 B2.6 错误码归因口径（默认排除 400/413/422，可配），不采纳"4xx 一刀切不计"——401/403/429 多为渠道责任（用户此前拍板）。

指标窗口取 window_minutes（15），样本不足沿用 B2.8 稀疏回看取比率指标；错误/成功计数按分钟桶天然精确。

## 2. 熔断与恢复

- **触发**：M < 0.1 → 权重置 0、优先级置 0（记原值）、入熔断态；
- **恢复**：静默 5 分钟 → 探针（每 5 秒 1 次共 10 次，agent 经 newapi 渠道测试接口执行）→ 按探针算 M_new = K_error_probe × K_speed_probe（cache/otps 因子=1，速度以组基线为参照）：M_new < 0.2 继续熔断 5 分钟循环；≥ 0.2 解除——优先级回原值、**软启动**首个调度周期 M 强制 0.2，之后正常；
- 探针链路：server 下发新命令类型 `channel.probe`，agent 复用 channelcontrol 凭证执行并回报（探测只打熔断渠道，成本厘级）。这是挂起的 v1.1 探测批次的落地形态。

## 3. 优先级

默认不动（保持手动配置的基础优先级）；仅熔断联动置 0 / 恢复。**值班模型的 demote/试岗退役**。

## 4. 节奏、写入与护栏

- 每分钟计算一次；`W_realtime ≠ newapi 当前值` 才下发 channel.update（值相同不发，去抖）；
- **哨兵保留**：auto 命令过期未执行 → 暂停该站点自动写入并告警；
- **人工优先（新语义，闭掉旧欠账）**：newapi 内的值由 CT 写入，人工调整应改 CT 基础值。检测到 newapi 当前值 ≠ CT 上次写入值（有人绕过 CT 手改）→ 该渠道暂停自动写入、页面提示用"一键同步"回填或覆盖；
- 冷却/每日动作上限**退役**（离散动作护栏对连续控制无意义；安全性由基础值锚点+上限 clamp+熔断线+去抖替代）；
- 混布保险丝、no_backup 类信息提示、错误归因、稀疏回看、审计与命令链路全部**保留**。

## 5. 配置与交互

- **每模型独立三态开关**：off / observe（算而不写，页面展示拟写值）/ auto（写入 newapi）。observe 是原方案之外补的灰度档；
- **基础值配置界面**：按模型分组编辑各渠道 W_base 与基础优先级；
- **一键同步**：读 newapi 当前权重/优先级回填配置界面（多选模型批量），仅回填、保存才生效；
- 建议流水改造为**变更流水**（每次写入、熔断、探针、恢复事件）；命中率报表语义作废，新观测指标（熔断次数/探测成功率/权重稳定性）记档后续。

## 6. 调权中心页面重设计（2026-08-01 用户指示，随 B2 落地）

围绕连续配权模型重构，退役所有值班语义区块。页面五个区块：

### 6.1 调度总览（核心区块，合并原"梯队总览"与"基础值配置"为一张可编辑状态表）

按模型分组，每组表头带该模型的**三态开关**（off/observe/auto）。每渠道一行：

```
渠道名 | 状态签 | 基础权重(可编辑) → 实时权重 | 倍率 M(悬浮看四因子分解) | 基础优先级(可编辑) | newapi 实际值对照
```

- **状态签**：正常 / 熔断中（含下次探测时间）/ 探测中（n/10）/ 软启动 / 人工接管暂停 / 哨兵暂停；
- **倍率悬浮**：K_speed/K_cache/K_otps/K_error 各自数值 + 其输入指标（TTFT 三元组、缓存命中、OTPS、错误衰减状态）；
- **newapi 对照**：实际值 ≠ CT 上次写入 → 行高亮"人工接管，已暂停自动写入"，行内提供"同步为基础值/恢复自动"两个动作；
- 表格顶部工具栏：模型多选 + 一键同步权重/优先级（B1 已建，回填标黄、保存生效）。observe 档下"实时权重"列显示**拟写值**并标注"observe 未写入"。

### 6.2 参数区（大瘦身，替代旧 scheduling/criteria/dynamic_weighting 三区）

- 可配：λ 敏感度（默认 1.0）、K_otps 上限（1.5）、熔断线（0.1）、恢复线（0.2）、熔断静默（5min）、探针间隔/次数（5s/10）、软启动倍率（0.2）、指标窗口（15min）、最少样本与稀疏回看两项（沿用）；
- 说明卡：一行公式 `实时权重 = 基础权重 × K_speed × K_cache × K_otps × K_error（上限 1.5）` + 四因子一句话解释 + 熔断→静默→探针→软启动流程图（复用现有 dispatch-flow 样式）；速度因子权重 0.5/0.3/0.2 与错误衰减 0.8/1.08 为定值不开放（防调坏，改代码才能动）。

### 6.3 变更流水（替代"建议流水"）

事件型时间线：权重写入（before→after+倍率+因子摘要）、熔断触发、探针轮次结果（n/10 成功）、恢复+软启动、人工接管暂停/恢复、哨兵暂停。按模型/渠道/事件类型筛选。confirm 采纳交互退役。

### 6.4 观测指标卡（替代命中率报表）

7/30 天：自动写入次数、熔断次数、探针成功率、人工接管次数。命中率语义作废；权重稳定性指标记档 B3 后评估。

### 6.5 说明区

面向运维的一段话版本：模型是什么、三态开关含义、人工想干预时的正确做法（改基础值，别去 newapi 手改）。

## 8. 对照取舍记录（相对外部方案）

采纳：基础值锚点（消除现方案复利漂移）、K_error 指数衰减（反应速度）、熔断+探针+软启动（替代试岗，用户零感知）、优先级默认不动、每分钟节奏、每模型开关、一键同步。
偏离：速度因子用 TTFT 三元组（P90 数据现实）；错误口径用错误码归因而非 4xx 一刀切（用户既有拍板）；补 observe 灰度档；保留哨兵/审计/归因/稀疏等 v2.9 基础设施。
退役：demote/trial 值班机制、旧 rebalance 算法（当前×倍率）、动作冷却与每日预算、confirm 采纳链路（连续控制无离散建议可采纳）。
