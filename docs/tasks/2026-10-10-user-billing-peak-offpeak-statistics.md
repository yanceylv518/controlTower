# 用户账单日列表峰谷明细

更新：2026-10-10。本地实现并验证；按用户要求提交并推送 main，完成状态以 Git 记录为准。未发布版本或远程部署。

## 最终需求与界面

用户明确：不需要独立统计，只在日账单统计列表中增加高峰、低谷统计，很多模型没有峰谷计费。

- 当前日账单工作区直接展示“日期合计 → 模型合计 → 高峰/低谷明细”三层行。
- 只有历史档位名称明确为高峰、低谷、空闲或 peak/off-peak 的模型添加第三层行；按日志原名显示并按折扣分行。不根据时间、当前价格、ratio或模型名称猜测。
- base、缺失档位、上下文档位等不显示峰谷行，普通模型保持原状。
- 复用原有请求数、普通输入/输出、缓存读/写、图像/音频、原价金额、折扣和折后金额列。不另加空列。
- 日期及模型合计不变，KPI只累计账单行，峰谷子行不会重复计入。
- 子行不提供不匹配的明细筛选或下载操作，空输出诊断显示“—”，不误用整个模型的空输出数。
- 原有全部展开/收起支持模型下的峰谷子行。
- 移除独立峰谷按钮、抽屉、查询/下载入口和额外Excel峰谷工作表；月/临时账单界面保持原状。

## 数据链路

迁移133的 billing_tier_statistics 保留。账单生成从 RequestDetail.Charge.MatchedTier 聚合；该值来自日志 other.matched_tier，金额沿用已有结算值，不重新计价。数据库读取仅对完成的用户日账单向 workspace 响应附加 tiers；展示按同一账单 MoneySnapshot 转币种。日账单行只显示明确的峰谷分组。

现有月来源复制统计数据的内部机制保留，但不提供独立月峰谷页面或导出。缺失历史统计的账单不自动重建；原日志没有峰谷信息的模型不会被自动划分为高峰/低谷。
