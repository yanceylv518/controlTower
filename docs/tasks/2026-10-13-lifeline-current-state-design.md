# 渠道生命线当前状态展示设计

- 标识：2026-10-13-lifeline-current-state-design
- 日期：2026-10-13（Asia/Shanghai）
- 状态：用户确认后已实现、验证并提交推送c8637a5d，随rc168远程发布；未部署。下文设计阶段的“未实现”说明保留为历史记录，以末尾实施交接为准。
- 目标：一眼看出每个渠道是否在常态探测、恢复探测、等待恢复或未探测，以及原因和后续安排。
- 范围：当前会话，main；现已实现页面、只读 API、调度观察留痕和迁移 138，不改变探针启停资格、恢复阈值或自动开启决策，不操作生产。

## 已核实的问题

现有生命线概览以时间范围内的应发/实发、成功率、错误、漏测、执行中等历史聚合为主。`ProbeChannelStats` 尚无当前调度状态，`HandleProbeOverview` 只补充当前渠道目录中无历史记录的渠道。历史“执行中”计数、最后探针时间或调权配置开启，均不足以证明渠道此刻仍在运行探测。现有自动刷新、异常筛选和历史明细应保留，不用更多统计卡片替代当前状态。

## 页面结构

1. 默认进入“当前渠道”。顶部保留站点、当前快照时间与刷新控件。此处不放历史日期筛选和大趋势图。
2. 状态数量同时作为筛选：全部渠道、常态探测、恢复探测、等待恢复、未探测、状态待确认。计数按唯一渠道，不把多模型重复计数；与页面搜索及模型筛选口径一致。
3. 主列表展示渠道名称/ID及模型、渠道开关、当前探测状态和原因、最近探测及后续安排、详情入口。未运行和无历史记录的渠道也必须显示，不沿用探针选择器“隐藏手动关闭渠道”的规则。
4. 点渠道后在页内切换到详情，保留原列表搜索、筛选、排序，提供明确返回入口。首先回答“现在做什么、为什么、下一步是什么”，然后展示逐条探针、恢复检测批次和状态变更。此方案替代首版在长列表下方堆叠详情的设计；正式实现还应保留分页及滚动定位。
5. “历史统计”独立承载原有时间范围、异常分类、排序和趋势图。历史错误次数不改变当前状态；历史记录中的渠道即使已删除仍可查询，但明确标为不在当前目录。

## 两个独立状态维度

渠道开关：已启用、手动关闭、自动关闭、状态未知。自动关闭必须有 CT 的确认依据，不能仅用 NewAPI 数字状态判断来源；手动接管但关闭未确认要明确标注。

探测状态：

| 主状态 | 展示依据与次级说明 |
| --- | --- |
| 常态探测 | 已确认常态调度在运行；区分周期等待、请求执行中、错误后加速。周期等待不标成停止，不能因零权重直接判断不探测。 |
| 恢复探测 | 已确认恢复任务正在进行；有可靠进度才显示第几次、已完成次数。区分任务已排队/等待回执和实际请求执行，不把“命令执行成功”当作探针全部成功。 |
| 等待恢复 | 已熔断，尚未发起下一轮恢复；展示静默期、下轮预计时间或等待原因。时间是预计计划，不承诺准点执行。 |
| 未探测 | 显示具体原因，例如手动关闭、常态总开关关闭、未选中、模型只观察/关闭、多模型不符合资格、没有可用配置等。停止请求后若仍有在途任务，明确“正在停止/取消中”。 |
| 状态待确认 | 状态读取失败、心跳过期、目录与运行状态冲突或缺少执行确认。显示最后确认时间；不伪装成未探测或健康。 |

故障恢复不受常态探针总开关/指定范围影响，因此恢复状态先于“未开启常态探针”展示；详情仍分别说明常态探针配置与恢复执行状态。手动关闭保护优先，不能显示仍有自动恢复计划。

模型较多的渠道在主列表只占一行，展开显示涉及的模型与各模型记录；不把不同模型的历史结果串在一起。优先级/线上权重以渠道开关下方的小字展示，详情概况也保留，不新增宽列。

## 刷新与数据真实性

- 当前状态快照与历史时间窗明确分离。查看过去一小时不意味着展示一小时前的“当前状态”。
- 默认手动刷新，保留自动刷新选择；列表翻页、筛选、查看详情时不跳位。允许更新状态文字而不重载历史时间线，记录刷新保持独立。
- 当前状态需要服务端返回可靠的执行/调度依据及确认时间；不能在前端仅用近期探针条数反推。现有 policy、ContinuousState 和渠道目录可解释资格与阶段，但不足以证明常态工作线程正运行；实现阶段需补充只读的调度确认/心跳信息，具体接口方案在设计确认后确定。
- 快照读取失败保留上次内容并标明过期；切站清空旧站点状态。历史接口成功、当前状态读取失败应分开报错。
- 只展示现有流程，不修改探针开关、恢复阈值、熔断或自动开启逻辑。该页面不新增启停按钮，设置仍在调权中心完成。

## 设计稿与验收

交互稿使用明确标注的合成示例数据，包含定时/加速探测、恢复中、静默等待、手动关闭、未选中、只观察和数据过期。支持状态筛选、名称/ID/模型搜索、渠道详情及历史入口，用于确认信息层级，不连接实际站点。

业务实现前确认：首屏能识别渠道当前状态；所有未探测项都有原因；恢复中与等待恢复不混淆；自动关闭与手动关闭不混淆；旧历史数据不会让当前状态误判；多模型不重复计数；移动端按渠道卡片顺序呈现同样字段。

## 探针发送记录设计补充

用户要求补齐完整效果，明确“先不要实现”。设计稿在每个渠道行增加“探针记录”和“状态变更”两个入口，打开同一详情区并定位到对应内容。详情提供探针发送记录、恢复轮次和状态变更三个视图。

发送记录展示发送/应发时间、是否发出、类型、模型、结果、耗时、说明及恢复轮次；支持时间、类型、结果、发送状态筛选与分页，默认全部结果，最新在前。未发送项显示应发时间和并发占满等原因，不假装已发送请求；错误行直接展示说明，记录 ID 和来源可展开。成功、渠道错误、慢请求、执行中、未发送、控制异常、取消及未确认均有合成示例。

恢复轮次可折叠展开逐条请求，分别展示计划、已发送、已完成、成功/错误/执行中数量。尚未发送的计划请求不计为漏测；整轮未结束不宣称渠道已恢复。轮次关联与进度必须由可靠数据提供，正式实现不能按时间相近猜测；没有逐条回执的 Agent 路径仍明确只有轮次结果，不补造逐条请求。

示例交互脚本核验了记录筛选、发送量计数、翻页与筛选重置、恢复轮次跳转/数量、空记录以及原状态筛选。仅用于设计稿内部交互验证，不是业务接口或生产端到端测试。本轮仅更新交互设计与记录，页面业务代码、接口和调度均未实现或修改。

## rc168后续：详情页签自动跳回（2026-10-13）

- 用户反馈：点击“状态变更”后马上跳回“探针发送记录”。截图同时显示快照已过期。
- 根因：当前状态每秒检查有效期；过期后 effectiveCurrent 返回新的渠道对象。详情使用返回数组的单一 watch getter，即使渠道ID等值不变，新数组仍触发回调，重置为初始入口页签并清空事件查询。由“状态变更”入口打开时也可能把其他页签拉回状态变更。
- 修复：改为多个独立 getter 分别比较导航值，仅站点、渠道ID、指定入口页签或批次真正变化才重置。同渠道的过期检查/快照替换保留当前页签、所选恢复批次、已应用事件查询与分页。
- 验证：新增两项响应式回归，修复前均失败、修复后通过；覆盖同ID对象连续替换、状态变更→恢复批次、事件入口→记录、真实切换渠道及入口。共27项生命线Web测试、pnpm typecheck、pnpm build、差异空白检查通过；构建仍有既有大包提示。本轮未运行浏览器或生产验证，无Go改动，未重复Go/数据库检查。
