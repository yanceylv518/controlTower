# 探针熔断与恢复缺口修复（2026-10-12）

## 当前状态

本地代码完成，未提交、推送、发布或部署。本次延续探针逻辑复核及用户后续澄清；不是探针分析管理页面的实现。

## 最终业务口径

- 正常探针按间隔发起；明确错误返回后立即继续发，仍错误则继续确认，计数达到门槛即熔断。保持从最近一次发起计时，不另加独立补测时间表。
- 慢请求和明确渠道错误使用两个独立计数器，互不清零。正常成功返回同时清零，阈值仍使用现有配置（默认两慢或三错）。
- 慢→错→慢触发；错→慢→错→错触发；慢→错→成功→慢不触发。
- 控制链路异常、取消、未发起等不当作渠道明确错误；未知覆盖仍中断证据。中间存在未决结果时不能跨过它拼接两段失败，但可检查它后方已经完整确认的失败段。

## 修改

1. 常态探针检查已确定的发起序号连续段。前方无关挂起请求不再阻塞后方完整故障证据。既有物理并发限制保留，等待结果的证据容量同时为可配置的慢/错阈值预留空间。
2. 恢复必须完成原下发命令要求的全部次数，不能以当前被改小的配置或部分成功率放行。未完成或异常数量的轮次返回静默等待；全部完成后仍需达到原恢复标准，并保留容量与禁用归属检查。
3. 共享恢复执行器标记取消/超时中止，直连和Agent把这类执行回执记为failed，同时保留已经完成的探测数据。达到慢阈值提前结束仍属于已获得失败证据，不能用于恢复。
4. 修正关联旧常量：Agent回执入口与MySQL记录不再把慢计数硬编码上限2；恢复启用执行前校验读取配置的RecoveryMinWeight。默认值不变。
5. 页面配置标签和使用说明同步独立计数及恢复完整性规则。既有字段名probe_slow_streak、probe_slow_limit及routine_error_limit保持兼容，无新增迁移。
