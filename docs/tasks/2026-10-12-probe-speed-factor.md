# 探针完整耗时参与普通调权

2026-10-12，用户要求新增探针速度系数，并明确选择“按完整请求耗时接入”。本地实现和验证完成；未提交、推送、发布、部署或调用真实上游。

## 计算规则

新增独立探针系数 Kp：

```text
Tchannel = 当前窗口内有效定时探针耗时之和 / 样本数
Tbaseline = 同站点、同模型合格渠道的 Tchannel 算术平均值
Kp = clamp((Tbaseline / Tchannel)^(探针影响指数 × 全局敏感度), 探针下限, 探针上限)
目标权重 = floor(基础权重 × clamp(Ks × Kc × Ko × Ke × Kp, 综合下限, 综合上限))
```

默认影响指数 0.25、下限 0.8、上限 1.2，均可在规则设置中调整。指数允许 0，表示仅关闭该系数，不停用常态探针或故障熔断。旧配置缺少新字段时补默认值，明确保存的 0 不被覆盖。

沿用现有 `window_minutes` 和 `min_samples`；没有修改用户的最少样本配置。每渠道达到样本门槛，且同模型至少两个非熔断、单模型、基础权重大于 0 的渠道合格，才形成基线。每渠道先求自己的平均耗时，再对渠道等权平均，避免采样数量差异改变渠道在基线中的权重。

探针证据可以独立使渠道参与普通调权，不要求该窗口同时有业务请求或 TTFT/OTPS 样本；缺少的其他性能系数仍按既有规则取中性值，错误系数保持原有逻辑。容量限升、写入版本检查、故障熔断及禁用恢复仍优先。正常性能权重 0 可由普通计算升权；按用户后续确认，已完全移除“三次健康即恢复小权重”的兜底。性能零权重始终保持正常阶段，仅由普通调权升权，不进入静默、恢复轮次或软启动；证据不足时保持当前权重。故障熔断仍保留专门恢复流程。

## 数据口径与保存

- 使用 CT 发出到完整返回的实测耗时，保留亚秒精度，不使用 NewAPI 日志中的整数秒，也不混作 TTFT 或输出速度。
- 仅纳入每 10 秒定时发起的探针；成功使用实际耗时，慢请求按 30 秒计。明确错误、传输错误、主动取消、容量不足跳过及加速补测不进入速度排名。迟到成功不重复记录。
- 按发起时间归入分钟，只读取当前分钟之前已经结算的样本；最近有效样本发起时间距评估超过 90 秒时不具备调权资格。样本不足、基线不足或停用时 Kp=1，不复用旧探针系数；没有其他充分证据时保持已执行权重。
- 每次探针结果通过有界异步队列保存，避免数据库延迟阻塞 10 秒发起与快速熔断。队列满会丢弃速度样本并记录日志，不据此判定渠道故障。
- 新迁移 `135_probe_speed.sql`：分钟统计表及状态 JSON；统计按渠道、模型、基础值版本、接管版本隔离，旧版本结果不参与当前计算。每分钟分批清理超过 48 小时的数据。状态、系数、基线与样本数写入调权状态和事件证据，页面展示第五项系数及计算依据。
- 依赖前一任务的常态探针，因此仍仅为已配置直连控制的自动模式渠道产生样本。恢复检测轮次和即时补测不纳入日常速度排名。未修改 NewAPI 或 Agent 日志采集。
