## 已确认代码行为与风险

1. `SaveReport`逐段写入：样本、指标事务、系统状态、渠道和Nginx数据。任何后续失败使Handler返回500/save_failed；整个report没有统一事务。因此部分指标成功和整轮失败可以同时发生。Handler未记录底层错误，健康接口成功不能排除CT数据库写入错误、死锁或字段约束。
2. `bufferFailedPass`清除NginxTimingBuckets/NginxSlowSamples后才写磁盘缓冲，Nginx队列独立保留。因此磁盘缓冲统计不代表完整失败请求。Nginx解析path仅去query，没有长度限制，目标列VARCHAR(500)，严格模式下超长路径可能导致写入失败；sumTiming也未拒绝NaN/Inf，可能在JSON编码阶段失败。尚无现场超长路径/非有限值证据，不将其认定根因。
3. 缓冲队头上报或本地DropFirst失败会立即退出，后面的心跳和新report不执行；无毒批次隔离。连续失败最长等待5分钟，明显大于实时覆盖90秒有效期，放大成页面503。永久毒队头不能单独解释后来恢复，需与瞬时失败区分。
4. Server有条数、压缩2MiB及解压8MiB限制；Agent部分裁减可选维度，但没有发送前全量字节检查/分包。已见486条指标不支持条数超限，字节大小及原始Nginx段未知。
5. 本地缓冲上限按日志+样本+指标总数计数，默认5000；Append或成功上报后的state.Save失败均能使轮次失败。当前缓冲仅一批且游标推进，对持续磁盘不可写或队列满的支持较弱。
