# 持续超限主动降权方案

状态：用户随后要求“再看看此方案有没有潜在问题，没有的话，就按这个来实现”，已完成复核、实现和本地验证。尚未提交、推送、发布或部署；生产效果待升级后验收。

## 目标和边界

采用比例容量反馈、单轮降幅限制、完整反馈窗口及滞回恢复。自动模式执行；观察模式展示建议；关闭模式保持原行为。容量控制不修改基础权重、优先级、分组，不因容量问题禁用渠道或拒绝请求；错误熔断保留独立保护。

权重影响相对分流，不能保证绝对TPM上限。单渠道独占、最高优先级无替代、分组隔离、候选容量耗尽及请求Token规模变化时，必须如实说明能力边界。

## 实现默认值

| 参数 | 建议 |
| --- | --- |
| 进入阈值 | 实际负载达到配置上限100% |
| 首次降权确认 | 新的有效数据持续超限至少60秒 |
| 目标利用率 | 90% |
| 单次容量最大降幅 | 25%，整数权重允许最少下降1的明确例外 |
| 反馈等待 | 仅超限保护有效时，写入确认后收到窗口起点不早于权重生效时间的完整60秒负载窗口；普通调权不独立触发限升 |
| 解除条件 | 所有已配置项严格低于85%，以新数据持续确认60秒 |
| 容量最低权重 | 1；不把已有熔断权重0提高到1 |

## 决策规则

1. TPM/RPM分别除以各自正上限，取最大利用率u；上限0的项忽略，两项不相乘。用Agent统计截止时间推进判断，重复窗口不累计确认时间；缺失、过期、不完整数据不能视为0。
2. 首次u>=1立即进入限升状态。有效超限证据持续60秒才主动降权，期间回到u<1取消本次降权确认，但不解除限升；解除仍须低于85%持续60秒，避免100%→95%就恢复上调造成循环。原有性能下降和错误保护仍工作。
3. 检查实际模型/分组/优先级的分流条件。每个分组均需有同优先级、正权重、未熔断/暂停、错误率未达轻度阈值的替代渠道；配置容量的替代渠道利用率须低于85%，且未处于容量保护/待执行状态。部分分组缺替代或分组未知时保持限升，提示分流空间不足；未配置上限的替代渠道允许逐步尝试，但标明余量未确认，不当作无限容量。多个超限渠道不会互相作为有余量的替代。
4. W使用最近确认的实际权重，不用基础权重或待执行目标：

   Wraw = max(1, floor(W * 0.90 / u))

   本轮允许下降量 = max(1, floor(W * 0.25))

   Wcapacity = max(Wraw, W - 本轮允许下降量, 1)

   仅在W>1且超限确认、反馈等待、分流条件满足时应用下降。W=1继续超限显示已达容量权重下限。
5. 普通最终目标取性能目标与容量约束的较小值。25%仅约束容量原因的下降，不阻挡性能惩罚或错误熔断；容量目标可低于性能倍率下限。性能样本不足时保持原性能目标，但有效实时负载仍可触发容量下降。
6. 直连必须收到写入成功确认；Agent队列必须收到执行回执，入队不代表生效。确认前同一渠道不堆叠普通调权/容量命令，页面展示正在执行的目标。熔断置零可以替代未领取的旧容量命令。失败沿用写失败保护，不计作降权成功；数据/配置变化造成的主动取消不计入写失败，也不触发整个站点的过期命令保护。
7. 仅已触发超限保护时，写入确认后等待完整的新负载窗口，禁止性能上调抵消容量下降。窗口起点达到最近权重生效时刻后，才允许下一次容量下降。等待期间更强的性能下降/熔断仍可执行，新的权重变化重新建立反馈基准。未触发超限保护时，普通性能调权成功不进入反馈限升；仍受单次上调、待执行回执及数据可用性门禁约束。
8. 反馈后u>=1按新负载继续计算；0.85<=u<1保持容量约束，不为退出而继续压低，也不立即加回；u<0.85持续60秒后解除。解除后沿用现有单次上调上限，不跳回基础权重。稳定在90%且长期限升属于预期行为。
9. 实时负载不可用时暂停新的比例容量下降、继续禁止有配置上限渠道的上调；有效性能下降和错误熔断保留。熔断恢复、软启动和待执行命令也应检查容量门禁，不能绕过保护扩大流量。

## 示例

W=100、TPM150万、上限100万，u=1.5，Wraw=60；单轮最多下降25，首轮Wcapacity=75。待新窗口覆盖该写入的实际效果后重算，不预设下轮一定降到60。若新负载在85%至100%，保持；持续低于85%才解除。

整数例外：W=2最小可执行下降为1，实际降幅50%，超过名义25%；说明中需明确。W=1保持可用，容量规则不写0。
