# 折扣显示浮点尾数修复

2026-09-30，用户反馈新版用户日账单明细的折扣显示为 `4.6000000000000005 折` 并换行。

## 原因和修改

- `BillingDailyDetails.vue` 直接输出 `Number(discount) * 10`，二进制浮点尾数进入展示文本；渠道折扣编辑列表、时间冲突提示及上游渠道按钮有相同写法。
- 新增 `src/utils/billingDiscount.ts`，将展示值限制到六位小数并去尾零。保存的折扣倍率支持六位精度，转换后的 `0.123456 → 1.23456 折`、`0.000001 → 0.00001 折` 均保留；`0.46 → 4.6 折`，零倍率显示 `0 折`，原价/空值/多折扣保持相应语义，非法值显示 `—`。
- 上述四处展示统一使用该函数，未配置渠道仍显示“未设置”。已有其他页面采用限精度格式化，未扩大修改范围。
- 原价与折后金额来自已存账单字段，前端这里没有参与费用计算。后端 `ChargeOriginal` 使用 `big.Rat` 输出六位折扣字符串，`DiscountLabel` 先用有理数乘 10 再格式化，没有相同问题。本轮仅改变展示，不修改费率保存、金额计算、导出、数据库或账单文件。

## 验证与状态

- `billingDiscount.test.mjs` 新增 3 项测试，覆盖常见浮点尾数、六位倍率边界、零折扣、原价、空值、多折扣和非法值。
- 与 billingGroups、billingTaskOptions、billingSourceMode、readonlyLogsBillingSummary 合计 26 项测试通过；`vue-tsc --noEmit` 通过。
- 使用本地 Vite 的实际 Vue 页面和模拟 API：8 行日明细按预期展示折扣，原价 `0.048874` 与折后金额 `0.022482` 的展示保持，渠道按钮、编辑列表及时间冲突提示均显示 `4.6 折`，无写 API 请求、无页面异常。验证脚本 `outputs/01a0eaeb-billing-sample/verify-discount-format.cjs`，截图 `discount-format-fixed.png`。这是展示回归，未对截图中的生产账单逐条审计。
