# 使用日志查询优化（2026-09-23）

基线：`df2d4f7c1`。本轮保留页面、接口、权限范围、时间边界、排序分页、默认消费统计口径、最近一分钟速率及已有缓存时长。不修改 NewAPI 表结构或索引，不强制指定未经生产执行计划验证的索引。

## 改动

- 错误码：提取六种原匹配模式的公共边界和分隔符，每个内容字段只调用一次正则；仍分别匹配 `content` 和 `other`。不增加或删除任何历史格式。
- 空输出：使用 `completion_tokens = 0 OR completion_tokens IS NULL`，保留 NULL 视为空输出的原语义。
- 最终记录：改写为顶层 `NOT EXISTS`；继续按同一用户、同一请求的 `(created_at,id)` 判断，空/NULL 请求 ID 保留，比较不受外层时间、渠道、类型条件限制。
- 链路展示：两次补查都限定当前页的请求/用户组合；同一记录的渠道序列只解析一次。viewer 不传输和解析最终不会返回的 `other` 链路元数据，但仍完成关联查询并保留 `fallback_checked` 的失败状态。链路不截断、不懒加载、不新增结果缓存。
- 原表统计：错误码、空输出或最终记录筛选下，同时到达的 count/stat 共享一条 COUNT/SUM 查询。COUNT 仍包含全部匹配类型，默认 SUM 只包含消费，显式类型按该类型统计。RPM/TPM 独立；共享查询失败回退各接口原读取路径。
- 共享只发生在查询进行期间：完成后立即移除。站点、角色、连接池、时间及全部有效条件隔离；最后一个等待者取消时停止查询。原有 5 秒接口缓存继续独立工作，不叠加新的过期时间。
- 分页游标继续使用优化前的筛选指纹，执行查询使用优化后的 SQL；已打开页面持有的旧游标仍能使用，站点、角色、用户、时间和筛选条件校验不变。

## 验证

- 原生 MySQL 8.0.46 独立测试实例，新旧 SQL 在三种排序规则下各比较 384 组筛选/权限组合，共 1,152 组全部一致：`utf8mb4_0900_ai_ci`、`utf8mb4_unicode_ci`、`utf8mb4_bin`。
- 对比首屏、OFFSET、两个方向的时间/ID 游标、COUNT、费用、固定时间窗口的 RPM/TPM；包含 NULL/零/负输出、空请求 ID、跨窗口最终记录、同时间不同 ID、时间与 ID 乱序、同请求不同用户、退款/登录类型、长文本和不同错误码格式。
- 新旧链路补查结果一致；并发测试验证一次扫描共享、单个/全部等待者取消、站点/权限/连接池隔离、统计错误互不连带、完成结果不额外缓存、链路详情失败降级。
- dashboard/auth/httpapi/mysqlstore 四个 Go 包测试及 vet 通过；使用日志相关前端测试 70 项通过。
- 本机 `CGO_ENABLED=0` 且未提供 C 编译器，未运行 Go race 检测。

## 二次准确性复查

发现并修复一个兼容性回归：旧游标的作用域哈希包含 SQL 文本及参数，三种筛选的等价 SQL 改写使旧游标返回 `400 invalid_cursor`。已先通过接口测试复现，再保留原有游标指纹格式；旧 SQL 仅用于生成指纹，不用于执行查询。上下页旧游标均通过，改变站点、角色、用户、时间、错误码或其它筛选后仍拒绝旧游标。

新增并通过以下检查，测试库为独立的本地 MySQL 8.0.46：

- 重新运行三种排序规则、1,152 组新旧查询对照，并增加每组游标指纹一致性检查。
- 遍历 100–599 全部有效错误码，每个错误码使用 13 组正文/other 样本，在三种排序规则下完成 19,500 组匹配对照。覆盖 NULL、大小写、数字边界、Unicode 空白、历史支持格式和跨列文本片段。
- 请求 ID 含大小写差异、重音字符、尾随空格、空字符串及 NUL，单条页面和混合页面共 318 组管理员/viewer 链路对照，结果与原实现一致。
- 实际调用列表接口遍历所有页并返回上一页，验证原查询的完整 ID 序列、用户范围及 COUNT，没有漏条、额外行或重复行。
- 真实 SUM 溢出时 COUNT 仍正确返回；修正测试数据后失败统计可以重新查询，未缓存失败结果。
- dashboard/auth/httpapi/mysqlstore 四个 Go 包测试和 vet 通过。

本次未发现新增的筛选、计数、费用或链路结果差异。以上为本地测试数据结论，尚未在生产数据与源库版本上验证。

## 本地性能对照

20,000 条合成日志，每请求四次尝试，含多用户、错误及空输出，错误正文约 420 字符。以下为统计 SQL 的原来两次扫描与优化后一次扫描对照，每项 3 次；不包含页面首屏、网络、RPM/TPM 或生产并发。

| 条件 | 原统计 SQL | 优化统计 SQL |
|---|---:|---:|
| 错误码 | 1,399 ms | 476 ms |
| 空输出 | 18.3 ms | 9.6 ms |
| 最终记录 | 310 ms | 172 ms |
| 错误码＋空输出＋最终记录 | 1,590 ms | 523 ms |

早期直接拼接六个完整正则的版本在该样本上出现退化，已废弃；最终版本提取了公共前后缀。性能数字仅适用于此本地样本；生产版本、索引统计信息、数据分布与文本长度仍需部署前后 EXPLAIN/耗时对照。共享扫描要求两个接口的实际计算时间重叠，不承诺每次请求都合并。

## 复现

在独立 MySQL 测试实例创建一个名称以 `ct_readonly_query_test_` 开头的空数据库，设置 `CT_READONLY_QUERY_TEST_DSN`。测试自动创建唯一的同前缀测试数据库，结束时只删除自己创建的数据库；勿使用源库连接。

```powershell
go test ./server/internal/dashboard -run 'TestReadonly(OptimizedQueries|ScopedFallback|RawSummary)' -count=1 -v
go test ./server/internal/dashboard -run 'TestReadonly(LegacyCursor|CursorStill|FallbackCollation|RawSummaryOverflow|AllStatusCodes|HandlerPagination)' -count=1 -v
go test ./server/internal/dashboard -run '^$' -bench '^BenchmarkReadonlyQueryStatsMySQL$' -benchtime=3x -count=1
```

本轮验证在本地完成，未打包或部署，未修改生产源库。
