# Excel 原价金额小数显示修复

2026-09-30，用户反馈导出明细中原价金额都显示为 0，而折后金额有六位小数。

## 原因

`xlsxwriter.Sheet.Row` 已按“金额”表头记录金额列，但普通 `AddReportSheet` 只有最后一列使用金额格式；其他数值列套用整数样式 `#,##0`。原价金额位于折扣之前，被误认为计数。对账表 `AddReconciliationSheet` 已正确使用金额列识别，因此本次截图的普通明细表暴露问题。

回归测试在修复前生成 XLSX 并解析实际单元格与样式，确认 `0.026696`、`1234.567890` 的数值仍完整保存，但原价列数字格式为 `#,##0`。前者显示成 0，后者也丢失小数展示。用户只提供截图，未读取其原始 Excel 或审计生产账单。

## 修复范围

- 金额列识别不再限于对账表，普通报表的所有金额列也使用 `#,##0.000000`。
- 保留既有末列金额行为、计数列整数格式、空原价“—”及真正的零金额。
- 不更改写入的数值、金额计算、折扣或币种换算；不修改源库和已存档案。
- `SettlementDetailReader.Export` 明细 ZIP、新日账单工作表、`RestyleSettlementDailyFile` 下载排版均使用同一个写表器，随 Server 更新生效。明细导出任务状态仅存于进程内，Server 重启后重新导出会从已存明细重新生成文件，无需重算账单。已下载的 Excel 不会自动更新，可自行将原价列格式设为 `0.000000` 或 `#,##0.000000` 查看小数。

- 新增真实 ZIP→XLSX 导出回归，检查原价 `0.026696` 和折后 `0.012280` 的数值及六位金额样式，零原价保留数值 0、未知原价保持文本“—”，导出前后原明细归档字节完全相同。
