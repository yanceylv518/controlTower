# 请求监控：固定 ALB 站点与可配置渠道判断规则

日期：2026-10-09。状态：已提交推送 main，随 v2.0.0-rc160 完成远程发布与产物验证；未生产部署。

## 用户确认与范围

- 首响应 P95、总耗时 P95、错误率任一达到阈值就进入关注列表，阈值可配置。
- ALB 只属于一个业务站点。此页面渠道固定绑定该站点，不随顶部站点选择变化，不跨站点排名。
- 原“重点慢渠道”更名“重点关注渠道”，最多 5 条，可按请求量或异常程度排序。
- ALB 请求大小/流量趋势与现有 SLS 连接保持原口径；渠道指标仍来自 CT/Agent 分钟聚合，不声称从 ALB 日志识别业务渠道。

## 实现

入口：请求监控 → 重点关注渠道 → 判断规则。

独立 request_monitor_rules 表，迁移 126；配置包含 site_id、统计窗口（1–30 分钟）、最低请求量、延迟最低有效样本、TTFT/总耗时秒阈值、错误率百分比阈值及版本。
默认值：5 分钟、100 请求、20 延迟样本、10 秒 TTFT、60 秒总耗时、5% 错误率。**站点默认空，必须由管理员选择 ALB 对应站点后保存，不猜测、不全局回退。**
配置 GET 允许 monitor.requests 或 settings.manage；PUT 仅 settings.manage，沿用登录/CSRF/操作审计保护；CAS 防止并发覆盖。
保存检查站点存在，渠道接口在 SQL 查询前按绑定站点映射节点；参数 site/instance_id 不可改变绑定。未绑定返回 channel_site_unconfigured，已删除站点不回退全局。

计算：
- 各指标独立校验分钟记录；坏 TTFT 不再排除整个渠道，总耗时与错误率仍可触发。
- TTFT/总耗时合并直方图后求 P95，不平均分钟 P95；总耗时支持旧 V1，与 V2 混用时精确降采样到 V1。
- 开放尾桶只能提供下限：V2 ≥90 秒、V1 ≥60 秒。下限足以证明达标则关注，否则列为待补充；不虚构尾部精确值。
- 错误率 = 有效错误计数之和 / 对应有效请求数之和 × 100，包含 CT 原有用户侧错误计数。错误率有效分母需达到最低请求量。
- 仅有效记录的请求数参与最低请求量判断；重复分钟不任选一条，也不重复计数。空白趋势保留 null，不补零。
- 同一渠道部分缺失时保留可用样本，并标记“部分数据”。未触发但存在未知指标且请求量达标者进入“数据待补充”，展示最多 10 条及总数。
- 异常程度排序使用已触发项的最大“指标值 / 配置阈值”，用于关注优先级，不自动禁用渠道。
- 图表数值四舍五入至一位小数，避免长浮点尾数。
