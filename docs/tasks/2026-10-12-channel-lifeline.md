# 渠道生命线、探针明细与可配置保留期

## 状态

按用户要求完成本地实现：独立探针统计管理页扩展为渠道生命线，合并查看 CT 探针、调权、禁用、恢复和其他已有渠道操作；默认仅展示最近 7 天，保留天数可按站点配置。未提交、推送、发布或部署。沿用 main，保留此前及其他任务的未提交修改。

## 页面与接口

- 新路由 `/channel-lifeline`，系统管理菜单「渠道生命线」，沿用 `tuning.manage`。调权中心渠道探针覆盖说明内可跳转到指定渠道。
- 站点、时间范围、渠道名称或 ID、模型及探针类型筛选；展示应发/实发、成功率、成功耗时、慢请求、错误、漏测、未确认与控制异常，含趋势、各渠道/模型概览及逐条记录。
- 选择渠道后查看生命线，默认突出操作、决策与异常探针；支持全部事件、渠道操作、未关联执行决策、探针。生命周期操作不受探针模型/类型筛选隐藏。
- 生命线合并直连请求、已有渠道命令、独立渠道审计及未关联执行的调权决策；同一命令对应多条建议不重复展示命令。推荐结果不是执行成功；展示实际回执、前后权重/优先级/分组/目标状态及关联标识。
- 逐条探针支持结果筛选，明细显示发起时间、定时/加速/恢复类型、耗时、慢/错误/漏测原因和判定截止时间。两类详情使用时间+ID 游标翻页；30 秒自动刷新仅在首页、相对时间范围及页面可见时进行。
- API：`GET /api/dashboard/tuning/probes/overview`、`records`、`lifeline`。生命线必须指定渠道；限制输入、时间跨度、分页大小，查询失败明确报错；切换站点或请求代次后丢弃旧响应。

## 统计口径

- 成功率 = 成功 /（成功 + 慢请求 + 渠道错误）；没有有效结果显示空值，不假定 100%。控制异常、取消、执行中、结果待确认及未发出的漏测不混入该分母。
- 成功耗时为 CT 请求完整返回耗时；慢请求到阈值即记慢，耗时记至阈值，后续晚返回不改变判定。含慢请求的平均/最大耗时属于“判定耗时”，不能视为完整返回耗时。
- 应发指调度器实际到达的发送机会；实发表示调用探测。停机期间、未启动调度任务期间不虚构应发数；图上无数据保留空档。
- 漏测沿用全局并发、单渠道并发、等待结果容量三种原因。慢/错独立计数、错误后连续加速和正常调权/恢复规则不变。
- 逐条记录从功能启用后开始积累，不从分钟聚合反推或补造历史记录。CT 直连恢复探针逐条保存；Agent 恢复探测沿用已有轮次命令与回执，尚无 Agent 逐条明细。

## 留痕与失败边界

- 迁移 `137_channel_lifeline.sql`：新增 `tuning_probe_records`、`tuning_probe_recorders`、`channel_control_requests`，补齐按渠道和关联命令查询索引。
- 常态探针记录发起、漏测与最终结果，独立于按序折叠的调权样本回调；取消退出等待观察者完成，后台约每 5 秒批量持久化，正常退出再补写。写入幂等，终态不能被旧 pending 重试降级。
- 常态留痕使用有界内存缓冲，数据库短暂失败保留重试；容量或最大缓冲年龄触发丢弃时记录丢弃次数/最近时间并在页面提示。它不是磁盘事务队列，进程崩溃可能丢失最近未写入记录。
- CT 直连权重/状态、优先级、分组、链路验证操作先保存调用意图再访问 NewAPI，随后保存最终状态。前置记录失败则不发送写操作；后置记录失败不把已成功写入变成可重试失败，保留 pending，查询超过写入期限显示结果待确认。
- 网络异常、超时或取消不能证明上游未执行，记录 `unconfirmed`；明确找不到渠道记录 `failed`。只保存白名单业务字段和标准原因，不把令牌、原始请求/响应或上游错误全文加入新明细接口。
- CT 直连恢复探针先存 pending 再执行，记录成功/慢/错/控制异常/取消。数据库前置失败归为控制不确定，不伪造渠道错误。
- 新请求和旧命令尽量通过命令 ID/决策 ID 合并；分组/验证的命令回链若在成功后写库失败，可能暂有两条相关记录，保留各自 ID 供核对，不能宣称跨 NewAPI/MySQL 事务完全一致。

## 保留与配置

- 配置路径：调权中心 → 规则设置 → 运行规则 → 探针与恢复 → **渠道记录保留天数**。
- 字段 `continuous.channel_history_retention_days`，默认 **7**，支持 **1～365** 整数天；既有配置缺省补 7，不允许 0 表示无限保存。
- 探针统计、逐条明细及整个生命线查询立即裁剪到该站点保留期，时间按记录发起/创建时间计算；缩短保留期后，即使后台尚未删完，页面也不再返回过期记录。
- 后台每分钟按站点分批删除过期探针记录和新增直连调用日志（每张表每站点每轮最多 10000 条），清理停用/已删除站点，过期记录器元数据同样清理。使用调用上下文限制查询和清理；大量积压分多轮完成。
- 既有 `operation_audits`、`channel_commands`、`tuning_recommendations` 是共享审计/调度数据，不在这个清理器中删除；本页只关联它们在配置保留期内的部分。原有探针速度和覆盖分钟表保留其 48 小时内部统计策略，不作一周逐条日志来源。
