# 上游URL优先、后台同步及错误上游删除修复

用户反馈 qujing 在已有中文名上游缺少前缀时被自动建成重复上游。本轮按新要求改为 URL 优先，再按前缀补充URL，均不命中才新建；补充后台定时同步及删除/合并入口。

## 实现

- 同步先遍历已有绑定，收集其当前URL，再处理新渠道；保留手动/历史归属和人工排除。唯一URL优先于前缀；共享URL只由候选所有者中的有效最长前缀消歧，否则待匹配。无URL匹配时按前缀并追加URL。新关联学到的URL下轮才参与匹配，避免同一批次渠道ID顺序影响归属。
- Server独立后台任务立即执行、每30秒轮询，最多4站并发，8秒单站查询/同步上下文，失败保留配置并重试。启用且有只读源、未删除的站点参与；API-only也运行。原按需入口和手动按钮保留。
- 上游弹窗显示前缀原归属；预览采用URL优先规则，并可一键勾选其他上游的匹配渠道后确认转入。
- 增加“删除上游”。有渠道必须选合并目标，一次转移全部渠道/前缀/URL；所转渠道折扣复制到目标、源规则保留，重叠则整笔回滚。双方revision核验，运行中账单阻止操作。
- 132迁移增加archived。有账单、生成任务或折扣历史时保留ID，停用且隐藏，清除匹配规则并取消后续生成范围；无历史则物理删除。源渠道和历史账单不改。已有重复上游需要用户选择正确目标合并，不擅自按名称批量合并。
- 更新删除API、当前契约和URL统计命令的迁移要求。单渠道转移原有“不转移折扣”规则保持，合并删除明确复制规则。

- 最终并发编辑回归暴露一次MySQL1213死锁；保存、同步、合并删除现复用至多三次整笔事务重试，仅重试确认死锁，重试重新核对revision，网络/提交结果不明确不重放。
