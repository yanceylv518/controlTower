# 常态探针首次错峰与漏测统计（2026-10-12）

## 状态

按用户“那继续完善”完成本地实现及回归，未提交、推送、发布或部署。迁移 136 为新增统计表；保留此前探针、调权、恢复及其他未提交工作。

## 调度与计数

- 各渠道首次探测按站点、渠道 ID 的稳定散列分散到一个配置周期内，之后沿用配置间隔。默认首发在 0～10 秒内；首次等待期间取消不会发请求，也不会记应发或漏发。
- 错误后立即继续发送，后续仍错误继续加速，定时间隔仍从最近一次发起重新计时。错峰不延缓已经开始的错误确认链。
- 两类调度分别累计：定时探针和错误后加速探针。各自有应发、实发、全局并发不足、单渠道并发不足、未决证据容量不足次数，以及最近应发、实发、漏发时间。恒等式为应发 = 实发 + 三类漏发。
- “应发”指运行中调度器到达的实际发送机会，不按墙钟时间机械推算。首次错峰、未启用/不符合常态探针条件、服务停机、清单或控制配置不可用而未启动任务等不虚构应发数。统计当前没有覆盖停机期间理论应发量，也不是端到端可用率。
- “实发”表示 CT 已取得容量并调用探测，不代表上游成功接收或健康返回。漏发不进入渠道错误、慢请求或调权耗时样本。证据容量不足时保留一个有界未知间隔，避免容量恢复后把间隔前后证据拼接。
- 常态探针既有健康/慢/错规则不变：慢和错计数互不清零，健康成功清零，未知覆盖打断；性能权重 0 继续探测并参与普通调权；故障渠道进入原恢复流程。

## 存储与页面

- `136_probe_coverage.sql` 新建 `tuning_routine_probe_coverage`，按站点/渠道/分钟/进程代次/调度类型保存累计快照。渠道工作任务重启不重置当前进程计数，进程重启使用新代次，查询累加各代次。
- 调度路径只更新内存计数；后台约每 5 秒批量写库，失败保留待写数据。绝对快照单调合并，重复、乱序及部分提交后的重试不重复累计。正常退出在生产者结束后补写一次。
- 沿用探针统计的 48 小时保留尺度，过期批量清理。正常运行仅保留各调度类型最近桶及待写桶；数据库持续不可用时内存保留最多 48 小时，过期丢弃打印日志。非正常退出可能丢失尚未落库的尾部统计；没有新增磁盘事务队列。
- 原 `continuous-states` 响应附带 `probe_coverage`，独立于评估状态条目。使用已保存的调权窗口分钟数，按分钟取窗口并包含当前未结束分钟，返回确切边界和最近入库时间。RPM/TPM 的 `rates_only` 路径不查询覆盖统计。
- 查询失败独立标为 `probe_coverage_unavailable`，不冒充 0 漏发，也不阻止原评估状态返回。页面区分未提供、暂不可用和窗口内无记录。
- 调权中心每渠道新增“定时探针 实发/应发 · 漏发”入口，可展开两类调度的完整数量、原因、最近时间和统计口径；桌面与移动页面均可查看，站点切换不展示上一站点统计。
- 顺带纠正探针系数及恢复探测说明中的旧硬编码数字，读取当前参数显示。
