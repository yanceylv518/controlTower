# 用户及上游空输出账单按需任务

## 最终方案（2026-10-14）

用户确认采用独立按需任务：不是所有账单都需要导出空输出订单，因此普通日账、月账和临时账单不额外保存逐单空输出明细。此前本会话的 JSON 快照表、月账复制和同步导出方案已撤回，迁移 141 已移除且未应用到运行库。当前实现无需新增迁移。

## 使用与语义

- 用户账单、上游账单顶部新增“空输出账单”。选择单个用户或上游、起止时间后提交，沿用现有最长 60 天限制并拒绝未来区间。
- 在持久化账单队列中增加独立 `bill_period=zero_output`；复用原有两种主体类型、权限、站点调度锁、分页游标、任务进度和失败重试机制。后台任务读取当前配置的数据源（只读日志或归档）。
- 过滤口径保持源日志 `completion_tokens IS NOT NULL AND completion_tokens=0`，不以展示层减去多模态后的普通输出字段重新分类。用户范围、上游渠道和模型范围继续生效；空输出诊断明细不因普通账单输入用量校验而漏掉。
- 来源、金额配置和上游绑定按既有任务机制记录；导出基于任务读取时仍可用的日志或归档，并非历史结算账单的逐单复刻。归档继续校验封存状态及版本。只读日志已清理的历史不能自动补回；无匹配时提示可用数据中无空输出订单。
- 已生成目录及按对象工作区均新增空输出分类；生成记录显示“空输出账单”。下载复用已发布 XLSX，后续下载不重新查询源日志或生成 Excel。成品存储路径沿用 billing files 根目录。
- Excel 含时间、源日志/请求/上游请求 ID、用户/令牌/渠道、模型、各类用量、单价、折扣及金额。按任务冻结币种和汇率展示；每 50,000 条拆分工作表。
- 相同范围正在执行的任务仍去重；已完成、无数据或取消后可以重新生成，保留既有任务历史。失败按现有入口重新提交相同条件重试。

## 性能与结算隔离

- 只有手动创建空输出任务时才增加读取和文件生成成本。普通账单没有新快照写入，月账没有空输出明细复制。
- 源 SQL 在分页 LIMIT 前过滤空输出；不会先拉取整页所有正常订单再进行前端筛选。数据库仍需检查选定范围内的候选记录，耗时取决于数据量和源索引。
- 复用现有后台调度和限并发机制；逐页写磁盘暂存，聚合沿用现有紧凑表；无逐单 JSON 数据库表。XLSX 通过可选 128 KiB XML 写缓冲减少小写入，分表时关闭上一工作表，压缩输出检查 context 取消。
- 完成任务不插入 `billing_statements`，不覆盖正常日/月账单、不激活日账版本。已完成/发布中的空输出成品不进入普通过期非活动文件清理；显式删除任务成品沿用账单删除接口。
- 任务仍占用队列、源数据库读取和临时磁盘；文件和暂存空间随空输出记录数增长。未做生产规模压力测试，50,001 条拆表测试只证明功能正确。
