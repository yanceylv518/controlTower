# 用户日账单列表按模型分组

2026-09-30，用户反馈日账单列表只按日期汇总，无法看出当天用了哪些模型，要求按模型区分。

## 已实现

- 新版用户账单的日账单列表默认展开为日期合计及其模型行。首列标明日期/模型，日期行提示模型数量；模型行显示该模型请求数、普通/缓存/图像/音频用量、原价、折扣、折后金额和空输出情况。日期仍可折叠，顶部 KPI 只累计日期行，避免重复相加。
- 模型行“查看明细”传入原作业 ID 和精确模型名，在明细弹窗初次请求前就应用模型筛选。再次从日期行打开会清除模型条件；按条件导出沿用弹窗筛选。整日下载入口保留在日期行。
- 月账单、临时账单及上游列表保持原行结构。旧 Server 未返回模型数据时保留日汇总并提示暂无模型汇总；空模型名显示“未记录模型”，不提供会误查全日的空模型筛选按钮。

## 数据与正确性

- `mysqlstore.BillingWorkspace` 对已完成的用户日账单改用同一个 CT compact 汇总表按模型分组，替代原来的单条总计查询。共享原 SQL 金额/折扣/历史原价回退表达式，不额外逐模型发 SQL，也不读取源日志、重扫账单明细文件或改变生成任务。
- 模型按二进制名称分组，合并同模型跨渠道/令牌行，同时保留大小写和尾部空格不同的名称。
- `SumWorkspaceModels` 按既有十二位小数金额字段用有理数求和；原价缺失在模型和日期层面保持未知，多种折扣不取平均。总计与每个模型均使用该账单冻结的币种快照换算。
- 当前作业加载仍沿用原有逐作业查询结构；本轮仅替换每日合计查询，不声称解决整个 workspace 接口的既有查询数量问题。
