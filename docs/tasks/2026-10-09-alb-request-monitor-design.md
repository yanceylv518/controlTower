# ALB 请求监控使用页设计（2026-10-09）

> 后续：用户已确认实现，正式页面和API已本地完成；当前状态以[实现交接](2026-10-09-request-monitor-implementation.md)为准。以下保留设计阶段记录。

## 最新决定

用户要求设计 ALB 接入配置对应的使用页面，并明确“先不对照 CPU、内存”。本次仅交互设计，不实现查询 API、周期采集或正式业务页面，不修改上一轮已实现的连接配置功能。

- 页面入口建议为监控分析 → 请求监控；配置仍在系统设置 → 外部数据源 → ALB 访问日志。
- 保留请求大小四档：<5、5–10、10–20、≥20 MiB。
- 大请求三条曲线作为主图；<5 MiB 保留独立纵轴的完整趋势，避免数量级差异压平大请求曲线。该呈现待用户评审，设计控制可切换四档同图。
- 暂不关联客户，不对照 CPU、内存；保留用户此前指定的少量高请求量、高延迟渠道。

## 页面顺序

1. 数据源连接状态、最新日志时间和统计完整截至分钟。时间范围默认最近30分钟，分钟聚合，建议30秒刷新（设计目标，尚未采集）。
2. 请求大小趋势：按全部 Host 汇总，支持域名/IP Host 下钻。所选分钟显示完成请求、大请求、超大请求、大请求占比、四档数量和大小未知数量。图例显隐不改变统计分母或总数。
3. 重点慢渠道：最多5条，不足不凑数；当前示例3条。近5分钟请求量与首响应P95同时达门槛且有效样本足够，支持请求量/延迟排序。独立标注CT渠道指标来源及更新时间，不因ALB Host筛选而错误过滤；名单固定按最新完整窗口，时间回看不重选名单。
4. 请求/响应字节趋势与Host汇总。流量图随Host及对照分钟联动；Host表始终显示全部Host当前完整窗口数据，点击对应Host筛选图表。

## 数据口径

- ALB指标来自SLS中的目标app_lb_id，全部Host均纳入。不把后端upstream_addr当作NewAPI上游业务渠道。
- 请求量仅是能查到的已结束请求日志；未结束/排队中的请求不在该数据源中。
- request_length是请求行、请求头和请求体总长度；size缺失/非法独立计数。
- 大请求占比=已知大小中≥5MiB数量/已知大小数量；完成请求数额外包含大小未知。
- 生产请求字节量必须聚合实际request_length，响应体字节量聚合body_bytes_sent，不按大小档位中点估算；设计中只是模拟数据。
- 图上的GiB/分钟是日志窗口字节量，不是实时网卡带宽、CDT账单或上游渠道公网流出。
- 渠道近5分钟P95应合并原始样本/直方图，不能平均分钟P95；示例阈值100次/5分、P95≥10秒、有效样本≥20需按生产负载校准。
- ALB与渠道不关联单个请求，渠道总请求量不等于大请求数量。

## 状态与交互

- 正常：显示截至14:38完整数据；14:39汇总中区域留空，不补零。
- 延迟：显示最新日志和截至分钟，缺数据区间保留缺口，不误判为流量下降。
- 未接入：请求与流量为空态，渠道数据可独立展示。
- 接入配置按钮展开目的地说明；正式实现时跳转到已有外部数据源设置。
- 可交互：Host选择与表格下钻、图例显隐、图表点选分钟/时间滑杆、渠道排序、配置说明；设计控制支持数据状态及小请求独立趋势切换。
- Host过滤仅影响ALB来源指标，当前不支持通过Host映射业务渠道。
