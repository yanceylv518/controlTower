## 统计链路

- Agent 沿用现有只读日志采集，不为页面额外查询源库。type=5 每条日志计一次，包含重试记录，不按请求ID去重。
- 按实例、分钟、客户、渠道、模型、错误码汇总。HTTP状态和业务码分别使用 http:/business: 命名空间，无法识别为 unknown；零输出消费日志独立计数，不进入错误总数、错误码趋势或占比。
- 原有分类器保留告警判定结果缓存；统计只上报类别和次数，不上报内容或凭据。大字段不会令整段统计失败，无法从有界解析识别时归 unknown。
- 初次启用先获取源表ID上界，从启用后新数据开始统计，不自动回填历史。统计状态文件 error-statistics.json 与主采集游标独立，重启沿用。共享源库部署仅启用一份监控采集，辅助节点保持 CT_LOG_COLLECT_ENABLED=false。
- 游标与待发统计同一原子文件保存；保存失败在主采集游标推进前返回，下一轮重读，上传失败不阻塞主报告，后台重试。
- 单次采集最多5000行，统计按最多2000组合拆包，不再因为第2001个不同组合直接丢弃。最多8000待发组合、64批，溢出移除旧批并记录累计丢失及最后丢失时刻。
- Server 使用实例+批次ID事务去重，与累加分钟统计同事务提交；重传、确认前崩溃均不会重复累计。分钟统计保留7天，去重账本保留31天；超过30天的旧批确认但不重放。

## 完整性与页面

- covered_until 表示采集已追到源表快照的时间，不使用 observed_at 上报时间冒充覆盖。
- 仅在已知源快照且积压排空时推进覆盖；末尾仅非监控日志时，少于采集页上限的结果也证明当前查询排空。
- 拆分采集页只有最后一包携带覆盖推进，避免前一包入库即把后续包尚未上报的分钟当作完整。
- 启用中间分钟、未采集尾部和历史未覆盖部分不展示为零。按1m/5m对齐完整桶；已覆盖且无错误的桶才补零。
- 丢失时保守排除截至最后丢失时刻的历史，后续完整分钟可以恢复；旧丢失记录无时间标记时拒绝展示完整总量。重新创建采集状态后只认最新启用边界，避免跨重置间隙补零。
- 覆盖是源表当时快照的证据，不能保证源系统未来不会写入回溯时间戳；后续刷新会重新汇总迟到记录。
- 原 MonitorErrorCodes 卡片改调用 /api/dashboard/error-statistics?timeline=true，通过完整实例维度键隔离对象，1m/5m范围与请求趋势对齐。保留懒加载、取消、拒绝旧响应、总览/错误码切换和展开单码。
- Top5与其他在SQL聚合；分钟返回最多6个类别，与错误日志量无关。错误码列表最多500项，截断长尾补“其他”且保留精确合计；列表中任意具体码可单独查询。总错误数始终排除零输出消费，占比以当前已覆盖范围的全部错误日志为分母。
- 使用一致性读事务保证总量、分布、时间桶一致。保持实例不匹配拒绝、查看者站点/客户隔离以及客户/渠道/模型权限，不放宽授权。
- 新页面不再调用 monitor-error-codes、不执行前端分段，也不在新接口失败时回退源库；旧接口和旧分段工具保留兼容。

## 再次复查（2026-10-10，本地修正）

维持 Agent 分钟预聚合、独立持久化上报和 CT 数据库事务去重的方案，不恢复页面扫描源日志。复查定位并修正以下问题：

- 队列溢出后，原先只有队尾新批携带丢失标记，较早的保留批次可能先推进服务端覆盖，造成暂时误报完整。新增独立持久化的优先缺口通知，先确认通知再发保留批次；旧通知上传期间发生新丢失，旧确认不会清掉新通知。旧状态升级及重启也先补发已有丢失标记。
- 统计不可用期间主采集游标继续前进，恢复后可能跳过一段日志。RecordPass 现在对照主游标与统计水位，发现跨越即持久化缺口，排除不完整历史；未知丢失条数不编造 dropped 数字，页面也识别只有 last_loss_at 的缺口。
- 首次启用时间若带小数秒，原 Unix 秒取整会把不完整起始分钟当作完整。改为保留时间精度对齐完整的 1m/5m 桶；API 同时拒绝非整桶的纳秒时间。
- 新采集周期已生效时，旧周期延迟批次原先仍可累加明细。现在持有实例状态行锁核对周期，只确认旧批次而不累加。实库复测发现 DATETIME(6) 的默认舍入与 Go 纳秒时间比较不一致，已显式统一微秒精度：起点向上、覆盖终点向下，避免误丢有效批次和误扩大完整区间。
- 显式 HTTP 字段中的 00429、+429 原先可生成不合法统计码并阻塞整批上传；现在规范为 http:429。补齐纯文本命名业务码与有界嵌套 error 对象解析，保留已有告警判定口径。
- 页面只按时间范围缓存会导致同一窗口内新聚合数据长期不可见。改为 15 秒缓存，并由父级监控序列刷新触发检查；原取消请求和旧响应隔离保留。
