# 上游多 URL 自动关联（2026-10-10）

## 用户确认的行为

创建上游时填写 URL，保存后自动关联当前站点渠道表中使用该 URL 的渠道。已有上游通过“新增 URL”追加地址：旧 URL 和旧渠道归属保留，不能因追加地址把旧关联清掉或转给其他上游。后续使用已登记 URL 的新渠道也自动加入。

## 实现

- `128_billing_upstream_url.sql` 新增站点级 URL 归属表。规范化后的完整 URL 使用 SHA256 唯一键；同站点只能属于一个上游，不同站点独立。只做追加和上游删除时级联清理，历史关联可用下述工具统计回填。
- HTTP(S) URL 去首尾空白、规范化协议/主机大小写和默认端口、去末尾斜杠；协议、非默认端口及路径仍参与完整匹配，不使用域名包含匹配。不接受账号密码、查询参数或片段。
- 创建 API 必填 `url`；编辑可追加 `url`，留空仅编辑基本信息。响应 `urls` 是已保存地址集合。忽略客户端提交的渠道/URL 列表，服务端从当前站点只读 `channels.base_url` 匹配。已有渠道被其他上游占用时保存拒绝，不抢占；数据库事务再次防并发冲突并回滚整次保存。
- 页面移除手动勾选关联，显示已登记 URL、新 URL 匹配预览及渠道 URL。重复地址或渠道占用给出中文提示；未匹配时仍可登记 URL。新增关联包含该渠道全部模型，原有手工模型选择及渠道折扣保留。
- 打开/刷新上游管理时用当前目录同步新增匹配；新账单创建、自动出账及新报表冻结关联前也接入同步。后台业务读取按站点共享 30 秒成功刷新缓存，管理页保存和刷新使用当前目录直接同步。没有另加常驻轮询：后续渠道在下一次读取或新任务时发现。
- 自动同步只追加成员/更新本上游渠道名称，既有渠道不因源 URL 变化、源渠道删除或源查询失败而转移/删除。失败不当成空目录，未登记 URL 的旧上游继续保留原关联。
- 已生成账单及在途任务继续使用冻结的渠道/折扣快照，URL 增加不重算历史金额。同步逻辑没有读取订单明细，也不写 NewAPI 数据库。
- 保存期间的 A→B→A 切站、卸载和旧响应已隔离，不关闭新表单或清除新提交状态。
