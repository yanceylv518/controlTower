# 熔断企微通知与实际动作对齐

## 问题与依据

企微/钉钉熔断消息共用 `mysqlstore.circuitEventAlert` 的摘要，原文仍为“渠道权重和优先级已置零”。当前普通熔断、批次快速熔断和恢复事件均不设置 `ProposedPriority`，实际只改权重。完整一轮探针零成功后才写入禁用；禁用后继续探测，满足恢复条件再启用并写入软启动权重。

## 修正

- 熔断消息明确权重归零、优先级保持不变，并说明静默、完整轮次全失败禁用及禁用后继续探测的后续流程。
- 恢复标题明确“软启动”，摘要说明软启动权重已写入、后续按策略评估，不暗示立即恢复全部流量。
- 只有事件证据 `channel_status=1` 时说明渠道重新启用；普通权重恢复不声称执行过启用。使用事件快照，避免通知延迟时读取后续状态造成错配。
- 保留自动模式、执行成功命令和 `auto_executed` 的通知导入门槛，不改变熔断算法、通知分类、发送时机或禁用事件的通知范围。
- 不回写历史告警摘要，不重发既有通知；部署新版 Server 后新导入的事件使用新文案，无新增迁移或 Agent/Web 要求。
