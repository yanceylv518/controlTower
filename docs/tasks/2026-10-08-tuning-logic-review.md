## 2. 控制对象与配置

控制范围按站点隔离，同站点按模型组织渠道。策略的 dispatch_modes 为每模型 off / observe / auto：off 不进入常规活跃模型评估；observe 计算与记录，不进行自动权重写入；auto 执行真实管理 API 或 Agent 命令。

渠道基础配置包含基础权重、基础优先级、RPM/TPM 上限与渠道归属；实际线上权重/优先级来自 channel_current。基础值和线上值是不同数据，自动权重以基础值为锚点，避免按上次权重反复乘倍率造成漂移。

多模型渠道因权重旋钮是渠道级而被安全排除；基础权重 0 是明确不分流配置，不参与正常恢复。CT 自己禁用的熔断渠道保留恢复资格及所有权，不能与人工禁用混为一谈。页面按开关/分组筛选仅影响展示，不能据此推断后台自动调权范围。

进入 auto 需要控制预检成功，Server 校验预检结果及 5 分钟时效。策略保存携带已保存版本/预期内容，服务端再次校验，冲突返回 409，避免覆盖其他窗口或哨兵的更改。

## 3. 数据链路与不同时间口径

1. Agent 默认约 30 秒一轮，读取新增日志、分类错误、形成分钟指标、专用速度证据和秒级请求/Token 负载；上报失败缓冲重试。秒级负载复用已读日志，不新增 NewAPI 查询。
2. Server 按指标批次幂等持久化，普通分钟指标与专用秒桶分流；调权查询以站点整合相关实例。
3. 常规 Engine.Run 每 30 秒调度；性能窗口默认 15 分钟，实际区间为 `[当前完整分钟-N分钟, 当前完整分钟)`。一分钟窗口也只取最近完整分钟；十五分钟是滚动范围，不是每轮等待十五分钟。
4. 错误记忆单独读取近 15 分钟桶，桶起点距当前满 90 秒后才折入；按 LastBucketAt 从旧到新处理，避免每轮重复折入。查询失败不生成恢复证据。
5. 实时 RPM/TPM 使用最近 60 秒已上报数据和覆盖截止时间，独立于性能窗口。页面每 5 秒刷新；覆盖不完整/超过 90 秒不可用，不解释为零流量。
6. 快速熔断直接接收本次上报增量，绕过普通窗口与 EWMA；入库侧剔除相对 Server 和报告时刻超过两分钟的历史桶，以及未来桶。

因此页面实时负载、本轮评估样本、平滑错误率、线上实际值可能来自不同时间。排障必须同时看窗口、覆盖时间、评估时刻与回执时刻。

## 4. 性能基线与公式

基线来自同模型当前参与渠道，各指标独立取合格渠道的算术平均，每项至少两个合格渠道。缓存不再依赖 TTFT 合格；无公共 TTFT 的非流式请求可以提供缓存/输出证据。已被 CT 熔断禁用的渠道不重新加入健康同行基线。

默认参数（站点保存的实际策略可能不同）：

| 项目 | 计算与默认值 | 证据门槛 |
| --- | --- | --- |
| 速度 Ks | R=0.5×P50/AvgP50+0.3×P90/AvgP90+0.2×P95/AvgP95；Ks=clamp((1/R)^(0.35×S),0.75,1.25) | 专用未重试流式 TTFT 样本至少 min_samples，分位数有效，同行基线有效 |
| 输出 Ko | clamp((OTPS/AvgOTPS)^(0.25×S),0.8,1.2) | 专用版本1证据、有效样本至少 min_samples、样本输出 Token 至少100、OTPS>0 |
| 缓存 Kc | clamp((命中率/平均命中率)^(0.15×S),0.9,1.1) | 渠道输入 Token 至少10000；基线渠道另需达到最低请求数，均值>0 |
| 错误 Ke | 平滑错误率映射分段曲线，节点间线性插值 | 渠道错误=max(总错误-用户错误,0)，分母为请求数 |
| 总倍率 M | clamp(Ks×Ko×Kc×Ke,0.5,1.5) | 仍受下述性能资格、容量、回执与熔断约束 |

S 默认 1，min_samples 默认 20。错误平滑 `E_new=0.3×桶错误率+0.7×E_old`；默认映射是 ≤1%→1，5%→0.85，15%→0.5，≥30%→0.2。

TTFT 只认可确认未重试的有效流式请求；重试、未知路由/缺覆盖计数单列，不能用“总请求很多”证明速度证据充足。OTPS 证据与公共监控指标亦分开。

当 TTFT 或其基线不足而本轮输出证据合格，Ks=Ko，所以 M=Ko²×Kc×Ke。当前实现和界面明确采用此替代规则，输出影响会变大。输出也不足时不能凭缓存或旧速度系数擅自重写正常权重。

公式目标 `round(基础权重×M)`，非熔断且基础权重>0时至少1。错误乘积很低仍可能被0.5下限抬高；熔断独立判断，不以 M<0.1 触发。

## 5. 从公式目标到拟执行值

实际顺序需要区分：计算四因子及公式目标 → 容量限升 → auto 单轮上调上限 → 熔断/恢复优先分支 → 样本不足保留已确认权重 → 容量降权目标 → 写入资格与精确去重。

- 默认 auto 每轮上调最多当前有效权重的10%，至少允许+1；普通下调没有这个限制。observe 展示不会用 auto 上调规则替代其公式结果。
- 样本不足时普通调权保持有效实际权重，不把0请求直接变成0权重；熔断、探针和容量控制仍有独立路径。
- 同一目标不重复写；普通权重命令有未确认结果时不叠加新的普通写入。
- auto 是权威配置：确认 NewAPI 外部改权重后重新覆盖到当前计算结果；旧 manual_override 永久暂停逻辑已退役。若人工需要长期干预，应改 CT 基础配置或退出 auto。
- 优先级独立保存/同步；正常性能调权不靠降低优先级轮换“值班梯队”。熔断/恢复本轮 weight 事件不再附带把优先级写0的旧动作。
- 写失败连续3次暂停渠道，默认10分钟后慢速重试；不能把配置过期取消算成控制失败。
- observe 事件采用相对上次已记录事件的5%基础权重死区（至少1），减少流水；auto 只用整数目标精确去重。事件少不等于未评估。

## 6. 容量保护闭环

利用率 u=max(RPM/MaxRPM,TPM/MaxTPM)，只计算已配置维度。首次 u≥1 立即锁住上调；超限持续满60秒才考虑容量下降。时钟使用 Agent 覆盖截止时间，重复读同一负载不会推进确认计时。

容量原始目标 `floor(已确认权重×0.90/u)`，最低1；单轮容量下降约最多25%，小整数2/3允许减1。例：已确认100，利用率1.2，目标75；利用率2.0时原始45，本轮仍先降至75。普通性能下降不受容量25%限幅限制。

降权必须检查可分流条件：同模型、同实际优先级、每个渠道组都存在正常可用同行；排除暂停、熔断、待确认、已进入容量保护、平滑错误率过高或利用率≥85%的同行。同行未配上限可继续，但原因标记容量未知；不能把“未配置”当作有已知无限余量。

无替代显示 no_headroom / no_eligible_headroom，不连续做无法改变分流的降权。容量权重只影响 NewAPI 相对选择，无法提供绝对 RPM/TPM 限流保证。

容量命令成功后等待完整60秒负载窗口覆盖确认时刻，再判断下一次下降。解除锁需要负载低于85%持续60秒；85%–100%保持，形成迟滞防振荡。缺覆盖重置观察计时但不凭空解除保护。

普通健康性能改权重虽然也跟踪回执，不激活超限反馈锁；只有真实容量保护 Active 才进入相应反馈等待。取消全部容量上限也保留在途命令确认，不丢失执行状态。

## 7. 熔断与恢复状态机

`normal → circuit（置零待确认/已确认） → 静默 → probing → soft_start → normal`；失败返回 circuit，持续静默后再试。

- 普通熔断：当前窗口请求达到 min_samples，平滑渠道错误率≥30%（默认）。
- 快速熔断：仅 auto，单次新鲜报告渠道请求≥50且渠道侧错误率≥50%（默认），不等待普通 EWMA。
- 置零命令仅排队时不是已停流；等真实成功结果，再以 Server 确认时刻开始默认5分钟静默。
- 静默后默认每5秒探测一次，共10次；自动探针使用 NewAPI 渠道测试接口，直连或 Agent 执行。
- 恢复判断：成功比例×探针速度因子≥0.2。速度因子使用公共监控P95恢复基线与成功探测平均时长，sqrt比值钳制0.1–1；与调权专用未重试TTFT基线分开。
- 达标后权重先恢复到基础值×0.2（至少1），确认后维持软启动周期再回正常；容量/未决命令可阻止恢复。
- 完整主动轮次全部失败时，CT 进一步提交渠道 status=2 禁用并持久化所有权，后续仍可探测；恢复达标再提交 status=1 与软启动权重。状态禁用/启用亦等回执。
- 探针丢失超时有回到 circuit 的保底路径；不会永久留在 probing。
- observe 不发送主动探针，用新增已沉淀真实流量作被动证据：累计至少 probe_count，错误率≤10%（默认）解除模拟熔断。真实已被 CT 禁用的渠道切 observe 不会自动重新启用。
- off 不再进入普通活跃模型评估；切换模式不等于自动还原之前已执行的所有线上字段。

## 8. 真正执行、门禁和丢失回执

站点已配置直连三件套时，Server 经管理HTTP执行（写超时15秒），成功后记录命令终态和 channel_current；没有直连则写 Agent 队列，由心跳领取执行并回报。直连配置损坏/调用失败不应被静默伪装成成功同步。

所有 auto 权重写入都走同一确认跟踪，与有无容量上限无关。pending/delivered不推进 LastWrittenWeight/LastWriteAt。只有 succeeded 才建立真实控制基准；失败回退未执行的熔断/恢复状态并计失败。

入队/直连前及Agent领取时重新检查当前auto、单模型归属、状态、基础值/上限/策略版本和决定标记；排队后配置改变或发现新实际权重，旧决策失效，等待下一轮重算。已经投递/开始HTTP的写入无法通过服务端开关瞬间撤销。

支持新协议的 Agent 对 delivered 超过2分钟自动写入执行 channel.reconcile：只读GET核对实际字段，目标一致确认，不一致标失败并同步真实快照，读取失败保留未确认继续核对；不重放旧PUT。旧Agent能力协商不会收到未知命令，但不能获得这项完整恢复能力。

变更流水关联 command 当前真实状态、错误摘要和确认时间，区分排队、已下发、成功、失败、过期；历史缺回执为未知。读回一致证明目标状态已确认，不能恢复丢失的原始执行时刻。自动流水与人工操作审计有各自记录口径。

## 9. 调度并发与页面行为

- 运行时最多4站点同时评估，每站点最多4渠道任务；同站点评估不重叠，忙时合并tick，不积压旧评估时间。
- 快速熔断4个独立报告处理器，不占普通站点工作池；同站点同渠道互斥、版本检查阻止旧正常快照覆盖快速熔断。已经运行的同渠道HTTP不能抢占。
- Agent不同渠道命令最多4路，同渠道保持顺序；采集周期扣除本轮处理耗时，失败保留完整退避。
- 页面进入时并行加载CT状态与直连刷新目录；未配置直连自动刷新静默跳过，手动刷新明确提示。Agent原约600秒渠道快照仍保留。
- 直连/Agent成功回执即时更新channel_current，晚到旧快照不能覆盖确认值；基础配置刷新与渠道目录刷新不同，前者是显式覆盖基础值操作。
- 页面状态/事件/基础值/策略30秒刷新，实时负载5秒刷新，最长25秒渠道变更长轮询；通知约100ms合并并触发全量运行状态刷新。
- 同站点查询失败/意外空状态保留上次成功结果并提示；首次无数据显示等待，真实0值可显示。站点切换、迟到响应和慢轮询有隔离保护。
- 基础值同步只更新基础配置已保存快照，保留未保存策略；外部策略变化无草稿自动接收，有草稿提示冲突。
- 每次评估保存参数/基础值/版本与时间，公式解释使用该快照；用户未保存草稿不能重写历史解释。界面“计算”“安全限制后拟执行”“当前实际”应分别阅读。

## 10. 当前限制与排障顺序

1. 无真实站点本轮取证：不能判断线上部署到哪个版本、容量是否实际分流成功或实际端到端延迟。
2. 基线为算术平均，离群值可影响同行；TTFT不足时输出系数参与两次；综合0.5下限与错误惩罚是当前取舍，未擅改。
3. 稀疏回看等参数仍在结构中，当前连续性能路径读取固定完整分钟窗口，不能仅因配置存在宣称已回看补样本。
4. 常规30秒、Agent心跳领取、完整分钟/90秒沉淀、容量反馈/迟滞均仍产生观察等待，直连并发不等于零延迟。满池/慢DB仍可排队；快路径队列满会丢该快路径，但普通持久化指标保留。
5. 同渠道互斥限当前Engine进程；没有本次新增跨Server分布式调权租约，多进程竞争未验收。
6. 旧设计正文“熔断优先级归零”“错误指数衰减”“中位数”“人工改动暂停”不能当当前规则。10月2审查文档的F1–F10缺陷章节是修复前历史，上方修复表和当前源码已取代。
7. 既有命令过期并发测试曾偶发锁观察超时，历史复跑通过不代表原因已解决。本輪未复跑真实数据库竞争实验。

遇到“计算与线上不一致”，先核对已保存模型模式/基础配置、评估时间与参数快照，再看速度/输出证据资格，随后看容量phase/sample_at、单轮上调限制与pending命令，最后查真实回执、错误/只读核对及channel_current时间。不要仅看公式或黄色图标下结论。
