# 上游日明细按渠道拆分

2026-10-08 用户反馈 rc156 的上游日明细 ZIP 仍以用户 ID 拆文件。

## 原因与修复

上游逐请求结算本身独立，但日下载使用 ListBillingStatementUserFiles，归档成员名明确拼接“用户-ID”。文件发布已有渠道 CSV 快照，导出链路未采用渠道维度。

新版上游发布从已计费的请求快照按渠道生成独立 XLSX（每工作表最多50000条），包含渠道名称/ID、模型、各类 Token、历史单价、原价、渠道折扣和折后金额，不包含用户/令牌分组。沿用已保存计费结果，不在导出时查询源库或重新计费。下载及完整归档优先采用当前账单任务的渠道 XLSX，ZIP成员名为“渠道-ID”。用户账单逻辑保持。

保留内部用户文件用于已有价格预览兼容。历史渠道 CSV 不含完整原价/折扣快照，不能安全替代现有已出账金额；旧账单沿用旧文件，需更新后显式覆盖重新生成才能使用新渠道格式。无新增迁移、Web/Agent改动。
