# 验收记录：渠道当前态迁移（2026-08-02）

范围：df7a401（未立项交付，含 merge 与遗留分支 codex/rc20-channel-current，惯例记档）。验收环境：Linux，Go 1.24.5 + Node 22。

## 结论：通过，零缺陷——且大概率就是"系统不流畅"的根治

渠道快照从"每次采集追加历史"改为"每渠道一行当前态"（channel_current），配套一次性历史清理。文档示例 4700 万行历史——此前名称解析（每 60s）、调权引擎（每分钟）、渠道页都在这张巨表上做 MAX+GROUP BY，正是慢的第一嫌疑。

- **021 迁移**：CREATE + 幂等 INSERT...SELECT（ON DUPLICATE 按 captured_at 守卫，重放安全）；
- **启动编排**：迁移独立 30 分钟超时（不复用 10s ping 超时）、迁移成功才起 HTTP、清理为启动后后台任务（5000 行/批、200ms 间隔、出错即停、下次启动续跑、完成有日志）；
- **删除守卫**：仅删已被 channel_current 覆盖（captured_at ≤ 当前态）的历史行；
- **读路径零残留**：全仓 grep 确认名称解析/调权/控制机选择/渠道页全部切至 channel_current，旧保留 runner 移除，`latest_only` 参数兼容保留；agent 零改动；
- 全量测试 + typecheck 绿；迁移/清理/upsert 均有测试。

## 部署要点（数据销毁型升级，比平常多两条）

1. **升级前必须备份数据库**（历史快照将被永久删除，文档已明示）；
2. 首次启动会慢（扫描历史表，上限 30 分钟），观察日志 `channel snapshot history cleanup` 直到 complete；
3. 清理不会立刻缩小表空间文件，勿在业务时段 OPTIMIZE TABLE。
