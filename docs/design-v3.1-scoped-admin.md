# 设计 v3.1：受限管理员（站点+用户范围的只读视角）

日期：2026-08-01。状态：**设计定稿，暂不实现**（用户明确先讨论后择期开工）。需求：某管理员只能查看 newapi 的部分用户及其日志/监控数据；newapi 无此权限粒度，且不改 newapi 源码——由 CT 承载受限视角。

## 1. 账号模型

CT users 表扩展（迁移，纯增量）：

- `role`：`admin`（现有账号全部归此，行为不变）| `viewer`（受限管理员）；
- `scope_site`：viewer 绑定的站点（"哪个实例的管理员"，用户拍板）；
- `scope_user_ids`：站点内可见的 newapi 用户 ID 集合（JSON，超管在 CT 用户管理处维护）。

## 2. 可见范围（用户拍板的三页面）

| 页面 | 数据源 | 过滤 |
|---|---|---|
| 客户监控 | CT 现有指标（instance_user 维度） | 站点+用户集合，API 层强制 |
| 使用日志（逐条明细，等同 newapi 日志页体验） | **server 只读直连 newapi 库 logs 表**（见 §3） | user_id IN scope 强制注入 + 分页/超时护栏 |
| 用户管理（**一期只读**，用户拍板） | 只读直连 users 表（余额/状态/用量等） | 仅 scope 内用户；改额度/禁用等操作留二期评估 |

其余页面与全部管理接口对 viewer 返回 403；菜单裁剪只是体验层，**安全边界在 API 层**（session 携带 role+scope，中间件统一强制，拼 URL 也越不过去）。viewer 的登录与查询行为写 operation_audits。

## 3. 只读直连（架构约定的受控破例）

原约定"只有 agent 碰业务库"（server 部署位置灵活）。为获得**全量+含历史+实时**的日志明细（agent full_debug 路线被否：存储翻倍、无历史、改绑定要重启 agent），对开通此功能的站点破例：

- 站点配置加可选 `logs_readonly_dsn`；未配置的站点 viewer 日志/用户页显示"未开通"，优雅降级；
- 数据库账号**只读、只授 logs 与 users 两表 SELECT**（需用户在 newapi 库手工建，是 CT 之外唯一动作）；泄露最大损失=日志可读，与 viewer 权限等价，无放大；
- 查询强制走 `user_id + created_at` 索引（部署时 EXPLAIN 验证）、强制分页上限与查询超时——不得拖累生产库；
- 直连仅服务于 viewer 明细/用户查询接口，CT 既有采集/指标链路不变。

## 4. 明确不做（一期）

用户操作能力（改额度/禁用——二期评估，需 newapi admin API 写路径与更重审计）；按 newapi 分组自动圈定 scope（组语义变动会模糊权限边界，先手工绑定）；viewer 自助改密以外的自助功能；跨站点 viewer。

## 5. 批次草案（开工令后细化为 codex-task）

- B1：账号模型迁移 + role 中间件 + 菜单/登录态适配 + 超管维护界面；
- B2：只读直连（站点 DSN 配置 + 日志明细接口/页面 + 用户只读接口/页面 + 护栏与审计）。
