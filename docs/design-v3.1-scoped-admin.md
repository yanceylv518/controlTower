# 设计 v3.1：受限管理员与用户账单

日期：2026-08-01。状态：**设计定稿，暂不实现**（用户明确先讨论后择期开工）。需求：某管理员只能查看 newapi 的部分用户及其日志/监控数据；newapi 无此权限粒度，且不改 newapi 源码——由 CT 承载受限视角。

## 1. 账号模型

CT users 表扩展（迁移，纯增量）：

- `role`：`admin`（现有账号全部归此，行为不变）| `viewer`（受限管理员）；
- `scope_site`：viewer 绑定的站点（"哪个实例的管理员"，用户拍板）；
- `scope_user_ids`：站点内可见的 newapi 用户 ID 集合（JSON，超管在 CT 用户管理处维护）。

## 2. 可见范围（用户拍板的三页面）

| 页面 | 数据源 | 过滤 |
|---|---|---|
| 客户监控 | CT 现有指标（instance_user 维度） | 站点+用户集合，API 层强制 |
| 使用日志（逐条明细，等同 newapi 日志页体验） | **server 只读直连 newapi 库 logs 表**（见 §3） | user_id IN scope 强制注入 + 分页/超时护栏 |
| 用户管理（**一期只读**，用户拍板） | 只读直连 users 表（余额/状态/用量等） | 仅 scope 内用户；改额度/禁用等操作留二期评估 |

其余页面与全部管理接口对 viewer 返回 403；菜单裁剪只是体验层，**安全边界在 API 层**（session 携带 role+scope，中间件统一强制，拼 URL 也越不过去）。viewer 的登录与查询行为写 operation_audits。

## 3. 只读直连（架构约定的受控破例）

原约定"只有 agent 碰业务库"（server 部署位置灵活）。为获得**全量+含历史+实时**的日志明细（agent full_debug 路线被否：存储翻倍、无历史、改绑定要重启 agent），对开通此功能的站点破例：

- 站点配置加可选 `logs_readonly_dsn`；未配置的站点 viewer 日志/用户页显示"未开通"，优雅降级；
- 数据库账号**只读、只授 logs/users/options 三表 SELECT**（options 供账单价格回退读 ModelRatio）（需用户在 newapi 库手工建，是 CT 之外唯一动作）；泄露最大损失=日志可读，与 viewer 权限等价，无放大；
- 查询强制走 `user_id + created_at` 索引（部署时 EXPLAIN 验证）、强制分页上限与查询超时——不得拖累生产库；
- 直连仅服务于 viewer 明细/用户查询接口，CT 既有采集/指标链路不变。

## 4. 用户账单（2026-08-02 讨论定稿，消费账单版）

- **金额口径（2026-08-02 三轮讨论最终定稿）**：按 token 单价逐项计算——`金额 = (非缓存输入(prompt−cache)/1M×输入价 + 缓存读取 cache/1M×缓存价 + 输出 completion/1M×输出价) × 分组倍率`。CT 维护两张配置表：**计价表（含阶梯，2026-08-02 用户补充——newapi 无阶梯计价，CT 补齐）**：主键（模型,生效日期,档位下限 tokens），单档模型一行下限 0，阶梯模型每档一行，每档三列单价/1M tokens（DECIMAL，带生效日期，调价/改档不追改历史）；**判档依据=单条请求的 prompt_tokens（含缓存，即上下文长度），整条请求落一档**（上游通行规则）；分档发生在日切聚合时（聚合后无法再分），billing_daily 带档位维度，按当日生效边界分类，改档规则只影响此后账单（追改历史=重跑回填）。**分组倍率表**（分组→倍率，默认 1；分组来自 logs 每条记录的 group 字段，日切汇总带分组维度）。金额查询时计算（改价自动重算）；**未配 CT 价的模型回退用 newapi 当前 ModelRatio 现算**（直连读 options 表换算单价，用户修正定稿：非 quota——quota 是当时倍率的实扣，回退要的是现价语义；含 newapi GroupRatio 故不再乘 CT 倍率；解析失败标"无法取价"），行带金额来源标注 ct|newapi；计价表页提供"从 newapi 导入价格"（ratio 换算回填为 CT 行）；quota 换算金额保留为对照列。**充值/对账侧不做**（用户确认充值不走 newapi 流水）；用户当前余额仅作展示列（users 只读直连）。
- **数据源（混合式）**：server 每日定时经只读直连拉**昨日** `用户×模型×日` 汇总写入 CT 库 billing_daily 表（append-only 日志→日切落定即终账，无对账漂移）；当日尾巴按需直连补一段（单日区间轻查询）；历史一次性回填任务。账单页查 CT 小表，不锤生产库。
- **页面**：账单列表页（选月+站点，每用户一行：消费额/请求数/tokens/当前余额；超管全站、viewer 限 scope，复用 §2 过滤中间件）→ 用户账单详情（按模型分组明细+按日曲线）→ 下钻链到使用日志页；CSV 导出（列表与详情）。
