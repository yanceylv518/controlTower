## 1. 页面目标和边界

让管理员首先回答三个问题：哪些日期的日志已经可靠保存；哪些日期满足归档侧出账条件；剩下的问题应该如何处理。

页面从展示执行节点、提交 ID 和累计行数，调整为展示日期覆盖、完整性和账单准备情况。执行参数仍保留，但放进任务与策略，不要求用户先理解游标、epoch 或校验摘要才能使用页面。

“日志已封存”表示某一版本已经通过规定的归档核验，不等于金额配置齐全、已生成账单或财务审批通过。“可出账”仅是当前页面范围下归档侧条件已满足的简写；正式提交仍需核验具体用户、精确时间、配置有效期、全局阻断、输入版本及权限。用户界面优先使用“归档条件已满足”，详情解释完整条件。

本页面不删除源日志，不修改 NewAPI 数据，不提供任意跳过核验后强行出账的入口。实时使用日志继续保留原页面；历史归档不与线上数据自动拼接。

## 2. 工作区与导航

全局只使用现有工作区顶部的一个站点选择器。页面、日详情、任务详情和范围检查共享其站点；弹窗只展示只读站点名称，不增加第二个可编辑选择器。

页面标题为“日志归档”，说明为“检查日志覆盖，准备用户账单”。页面内提供三个区，可用页签组织：

| 区域 | 主要内容 | 常用操作 |
| --- | --- | --- |
| 归档总览 | 当前采集状态、所选月份覆盖、阻断问题、待处理日期 | 查看缺口、进入每日数据、查看当前任务 |
| 每日数据 | 全日期列表、日志状态、出账条件、版本与核验时间 | 查看日期详情、补齐、重新核验、检查出账范围 |
| 任务与策略 | 运行队列与任务历史、执行节点、调度和保留策略说明 | 查看任务、重试、暂停或恢复、编辑允许的策略 |

切换页签保留当前月份与兼容筛选，不改变站点。切站后立即清除已选日期、前站点日详情和待提交参数；旧请求返回不得写入当前站点。加载期间使用骨架或加载提示，不能先展示前站点金额、条数或可用状态。

单站点可能存在多个历史数据集。总览明确当前采集数据集；历史日期标明所属数据集和代际，默认只在详情展开完整标识。同一站点的用户 ID、日期相同不代表可跨代际合并。范围触及不同 dataset/generation 时显示边界并要求分别处理，不能静默选择一代或相加。

## 3. 归档总览

顶部采集状态条显示“运行中 / 正在暂停 / 已暂停 / 离线 / 失败”，辅以最后成功时间、数据延迟和当前主要任务。运行状态与日志完整性分开：已暂停仍可能存在已封存可用日期；运行中也可能存在历史缺口。

所选月份使用三个紧凑指标：

- 归档条件已满足的日期数，分母为本月需要核验的已结束日期，明确按整日检查配置，不冒充已生成账单数。
- 待处理日期数及原因摘要，可进入相同筛选条件的每日数据。
- 今天的采集状态；已封存数量和版本在每日数据中查看。

覆盖起点之前的日期、今天和未来日期分别标识，不混入“应完成日期”的分母；接口同时返回统计边界，不能由前端根据首条现存日志猜测。指标来自当前站点、月份和约定范围的完整统计，不能对已加载一页求和后声称全月结果。

有中间缺口时展示“9 月 1–19 日中，18 天归档条件已满足；9 月 12 日待处理”，不能仅写“可出账截至 9 月 19 日”。无可信分母时显示状态数量与已知范围，不显示完整率百分比。

全局无法归期的收费异常置于指标前的持续提示中，例如：“有 1 条收费日志无法确定日期，新账单暂不可生成。”提供“查看异常”入口；不能只在某个日期卡片中显示，也不能被月份筛选隐藏。普通配置缺口、单日差异用较低层级的问题摘要展示。

连接错误显示“暂时无法读取归档状态”与重试时间；保留旧数据时必须写明“上次读取于……”，停用依赖新状态的提交动作。错误不能渲染为空月份、0 条或绿色正常状态。

## 4. 每日数据的状态和列表

### 4.1 日志状态与出账条件分列

| 情况 | 日志状态文案 | 出账条件文案 | 建议动作 |
| --- | --- | --- | --- |
| 今天仍在产生数据 | 采集中 · 今日 | 等待日期结束并封存 | 查看当前任务；仅内部预览 |
| 历史日期尚未补齐 | 待补齐 | 暂不可出账 | 查看原因、补齐并核验 |
| 已有日志，尚未完成核验 | 待核验 / 核验中 | 等待核验和封存 | 查看核验任务 |
| 源与归档有差异 | 核验有差异 | 暂不可出账 | 查看差异；按支持能力补齐或重新核验 |
| 源已清理且无可靠证据 | 无法验证 | 历史完整性未知 | 查看证据缺口，不提供无意义的一键通过 |
| 有有效版本，配置完整 | 已封存 · v2 | 归档条件已满足 | 查看版本、检查出账范围 |
| 有有效版本，金额配置缺失 | 已封存 · v2 | 待补金额配置 | 查看缺失时间段与处理入口 |
| 核验确认为零业务 | 已封存 · 0 条 | 归档条件已满足，或具体阻断原因 | 查看零日志核验依据 |
| 封存后发现变化 | 待修订 · 保留 v1 | 等待新版本 | 查看修订任务及旧版本 |
| 日期尚未到来 | 尚未开始 | — | 不提供选择或任务操作 |
| 日期早于可信覆盖起点 | 未确认历史覆盖 | 无法验证 | 查看覆盖说明 |

“0 条”只用于成功核验后的空集合；无上报、缺月表、查询失败且没有可信计数时使用“— / 数据未确认”并给原因。待补齐但已知部分归档数量时可以显示已存行数，同时保留“待补齐”状态，不能把部分行数称为全日总量。源已被清理后，两边都为空不能转为“已封存 · 0 条”。

上述出账条件是整日预览。有全局阻断时，已封存日期也要显示“暂不可出账 · 存在全局异常”；不能一边显示全局阻断、一边保留无说明的绿色可出账标识。金额配置仅覆盖部分时段时显示“部分时段配置缺失”，精确时间范围由生成入口重新核验。

状态使用文字、图标与颜色共同表达。已封存用中性或成功样式，采集中/任务中使用进行中样式，差异和未知分别表达；不能仅用红绿点区分“缺数据”和“零业务”。

### 4.2 列表和筛选

总览显示所选月的完整日历日期。每日数据默认“待处理”，同时提供“全部 / 归档条件已满足”筛选；后续可增加已封存或具体阻断原因。日期排序稳定，未来日期置灰但可识别；查看其他月份不修改全局采集状态。

桌面主列为日期、原始/消费日志数、日志状态、出账条件、版本/核验时间、操作。整数 quota 可在列设置或日详情中查看，必须标注配额单位，不把它显示为货币。提交 ID 和摘要不占主列。

“仅看待处理”下仍保留当前筛选说明；无结果显示“当前月份没有符合条件的日期”，区分“尚未建立日期覆盖”。不以隐藏已封存日期的方式改变顶部统计口径而不说明。

## 5. 日详情、版本和问题处理

桌面点击日期进入页内详情，保留应用外壳和返回入口；手机纵向展示同一详情，避免窄屏抽屉挤压字段。详情标题包括日期、站点只读名称以及日志状态，内容分为：

1. 日志概况：原始行、消费行、原始 quota、日志版本、最近有效核验时间。
2. 出账条件：封存、配置覆盖、归属/结构异常及全局阻断，分别说明结果。
3. 核验与差异：缺行、多行、字段不同及证据范围；全日核验与单批写入校验明确区分。
4. 版本历史：v1、v2 的发布时间、修订原因、当前指针和所关联的账单。
5. 关联任务与处理记录：状态、尝试次数、结果和可执行的下一步。

技术详情折叠展示数据集/代际、核验方法、schema/parser 版本和摘要；不展示 DSN、密码或未经授权的日志原文。缺历史配置引导到配置管理；无权限时只解释缺失内容，不显示可提交的管理动作。

旧版不能用“已失效”含糊表达已生成账单不可用。建议文案：“当前为 v2；已有账单仍使用 v1，金额和文件保持不变。”旧账单链接携带任务身份；不能跳转到按最新数据重算的实时结果。

查看差异不等于授权自动删除目标多余记录。缺行可以提交补齐；目标有源无要解释可能为源清理或删除，依据后端返回的允许动作处理。没有可靠证据时不提供“忽略差异并封存”。

## 6. 动作、异步过程和权限

### 6.1 补齐、核验与修订

“补齐并核验”提交前展示站点、数据集和明确日期范围，提交后显示“任务已排队”。后续状态按后端任务反馈更新为补齐中、核验中、封存中及完成；按钮点击、请求成功或源扫描完成都不能直接将日期改为已封存。

若后端只支持分开的补齐与核验任务，界面采用对应名称，不假装已有串联能力。已有同范围同参数任务时返回现有任务并进入详情，避免用户重复点击制造并行补扫。未知结果可重查原请求，不能盲目生成新幂等键重发。

“重新核验”明确针对所选日期，展示可能的读取负载与当前任务安排，不默认覆盖整个历史。任务失败保留上次有效版本及失败原因；是否可新建账单由权威目录决定，不由页面自行保留或清空绿色状态。

发现变化后展示“日志有变化，等待新版本完成核验”。新版本发布、旧版仍被账单引用与账单修订是不同动作。生成修订账单从已有账单的修订入口进行，归档页不直接覆盖或重新发布旧账单文件。

### 6.2 暂停和恢复

“暂停归档”只控制当前站点活动数据集的新采集/维护任务领取；已生成账单不因此不可下载。提交后显示“正在暂停，当前批次完成后生效”，后端确认后才显示“已暂停”。不能把按钮切换的乐观状态当成 Agent 已确认暂停。

恢复后显示“等待执行节点确认”，获得有效执行反馈后才显示运行中。Agent 离线或控制链路失败时显示实际状态，不因用户点击恢复就显示正常运行。暂停和恢复不修改归档版本、历史完整性或旧账单。

### 6.3 权限与能力

归档管理继续按现有权限体系处理；归档管理、账单创建和历史金额配置管理分别校验。拥有账单权限不自动获得补扫、策略编辑或异常处置权限。

所有动作同时检查后端 capability、当前数据集格式/状态与用户权限。后端未提供或不支持新版能力时，展示“当前服务尚不支持归档封存/账单联动，升级后可用”；相关按钮禁用或使用明确的说明入口，不能通过本地状态模拟真实成功。权限不足使用“需要归档管理权限”，与未升级分开。

同一站点的旧协议日志可继续显示 legacy 观测状态，但不把旧“已归档”记录映射成新版封存。页面筛选和入口不得绕过服务端能力、身份或权限检查。

## 7. 从归档进入用户账单

页面提供“检查账期”，用户选择连续日期区间，默认按北京时间完整自然日；输入明确标注“开始时间（包含）/ 结束时间（不包含）”，摘要保留精确起止时间。真正提交使用 `[from,to)`，不能在切换日期/时间控件时增减一天。

范围检查展示所选站点、数据集代际、日期天数、已封存天数、配置覆盖和阻断清单。例如：“9 月 1–19 日，共 19 天；18 天归档条件已满足；9 月 12 日有差异。”阻断项可定位到该日或全局异常，不只显示“校验失败”。

满足页面检查后进入现有账单生成流程，继续选择归档中的历史用户、模板与计费方式；首版使用固定版本系统模板，不依赖尚未实现的上传模板。此动作只打开生成流程，不立即创建正式账单。金额配置部分缺失时允许进入范围调整/问题说明，不能直接放行默认整日范围。

提交端重新核验用户属于该 dataset/generation、精确时间相交日期、配置有效期、全局阻断、权限与业务查重，并锁定同一目录快照的版本集合。前端预检成功不承诺以后一直有效；提交遇到状态变化时保留用户输入，展示具体变化并要求重新检查，不自动改账期、缩短范围或回退线上日志。

账期跨数据集代际时提示“此范围跨越两套源数据，需分别生成账单”，显示边界和拆分范围；不能按相同用户 ID 合并。旧账单已有相同业务范围时进入原账单或显式修订流程，模板变化不绕过查重。

## 8. 任务与策略

任务列表区分进行中与历史，主要字段为任务类型、日期范围、阶段、开始/结束时间、尝试次数和结果。进度依据真实已处理块/日期；没有可信分母时用阶段与已处理行数，不显示伪造的百分比。

任务详情保留每次尝试及错误分类：源不可读、目标不可写、源索引不足、身份不一致、历史无法验证、数据差异、配置不支持等。重试复用同一逻辑任务和参数；修改范围或身份需要新任务，不能让“重试”偷偷更换数据集。

策略区域收纳执行节点、时间延迟、回补窗口、批次预算、核验调度和配置观测状态。默认折叠高级参数；保存使用配置版本校验，冲突后提示读取最新配置。自动清理和冷存储作为后续能力说明，未实现前不提供可保存的假开关。

历史数据集处于 retired/只读状态时，可查看已封存数据和关联账单；管理动作按该数据集实际能力显示。页面不能把活动数据集的运行开关误用于历史数据集。

| 每日数据 | 表格按列比较状态 | 单日卡片，日期/两类状态常显，数量和主要动作次行 |
| 筛选 | 月份与状态筛选同行 | 月份常显，三个状态筛选紧凑换行 |
| 日详情 | 页内详情，核验与版本双列 | 同一详情单列，清晰返回；长内容纵向滚动 |
| 范围检查 | 时间双列、明确的区间摘要与逐项结果 | 时间单列，底部操作不遮挡最后一条阻断原因 |
| 任务/策略 | 任务表与折叠策略区 | 任务卡片，策略分组展示，长错误可以展开 |

优先复用现有 Element Plus、主题和移动布局约定，不建立第二套导航。1024px 表格保证关键状态与日期不依赖横向滚动；390px 卡片保留相同数据与操作，不能为了节省空间隐藏配置缺口或全局阻断。

长站点名、长错误、无名称的历史用户、多个阻断原因均允许换行或展开；精确时间不可仅用省略号展示。弹窗/抽屉打开后焦点进入标题或首项，关闭后回到触发点；加载、错误和状态更新对辅助技术可识别。明暗主题均不能只依赖浅色底区分状态。

## 10. 后端数据契约建议

以下是需要新增或扩展的逻辑能力，不声称已有对应 HTTP 接口；具体路径、客户端类型和权限在 P7 接入前统一确定。

| 逻辑能力 | 建议返回/接收的关键字段 | 必要行为 |
| --- | --- | --- |
| 页面上下文与能力 | site_id、活动/历史 dataset 列表、generation、格式/协议能力、权限、运行状态、期望与已确认配置版本 | 未知能力不默认启用动作；身份和站点明确绑定 |
| 月度覆盖目录 | dataset/generation、月份、coverage_from、catalog_revision、as_of、统计口径、逐日记录 | 统计与列表来自一致目录；缺失与已核验零值可区分 |
| 每日记录 | log_date、日志状态、current_version、核验时间、原始/消费行数、quota 字符串、archive_gate_state/reasons、allowed_actions | 归档侧条件与日志状态分开；NULL 不变为 0 |
| 全局阻断 | 当前数据集无法归期/无法确定影响范围的问题数量、原因、影响说明、允许的查看/处理动作 | 不受月份分页或日筛选隐藏；变化随 catalog_revision 更新 |
| 日详情与历史版本 | 版本清单、manifest 摘要、核验方法/证据范围、问题分类、关联任务/账单 | 已发布版本不可变；当前指针和旧版引用分开 |
| 提交维护任务 | dataset/generation、task_type、明确范围、参数摘要、幂等键、期望配置版本 | 服务端复核权限/能力；返回 task_id 与排队/已有任务状态 |
| 查询任务 | task_id、阶段、运行/排队状态、尝试、真实处理量、错误原因及可重试性 | 状态可恢复；任务提交成功不等于封存成功 |
| 出账范围预检 | dataset/generation、精确 `[from,to)`、catalog_revision、分日版本/阻断、配置覆盖；选用户后还含主体条件 | 明确只是预检；正式提交重新检查并固定输入 |

行数、quota 和超出 JavaScript 安全整数的字段使用十进制字符串；时间同时保留机器可解析值与显示时区。服务端输出稳定 reason_code 和允许动作，前端本地化文案，不能通过匹配错误字符串推断是否可出账。

响应必须携带请求对应的站点和数据集身份；前端以当前上下文及请求序号忽略迟到响应。目录版本降低或身份改变时重新获取，不拼接成完整月份。批量任务或范围预检中的部分失败逐项返回，不能以整体 HTTP 成功伪装成所有日期都已处理。

## 11. P7 验收与本轮验证边界

实现阶段至少覆盖以下场景：

1. 已封存、配置缺失、核验差异、未知历史、已核验 0 条、缺记录、今天、未来日期能明确区分。
2. 中间缺日不被“可出账截至日”掩盖；统计不受分页误算，覆盖起点之前和未来不计为逾期缺口。
3. 全局无法归期收费异常持续阻断，不能通过改月份、筛选掉异常、手工 API 提交或选已封存日期绕过。
4. 补齐/核验提交后只进入队列；重复点击不创建重复任务，失败或断网不乐观显示封存。
5. 暂停/恢复等待 Agent 确认；离线、失败与历史日期完整性互不冒充。
6. 日版本修订保留旧账单金额与文件；范围跨 dataset/generation 明确拆分，历史用户删除不影响已具备归档条件的选择。
7. 页面预检成功后目录或配置变化，正式提交正确拒绝或按既定选版边界固定快照，不换版、不缩短范围、不回退线上。
8. 无后端 capability、旧 Agent/旧格式、归档只读未配置和不同权限角色分别显示正确说明；仅前端隐藏不能代替服务端拒绝。
9. 1024px 桌面与 390px 手机、明暗主题、长文本、加载/空态/错误、键盘焦点及抽屉返回完成真实页面检查。
10. 生成入口、日详情与账单详情使用同一站点/数据集/任务身份，切站及迟到响应不串数据；导出仍由 P6 核验固定输入与文件范围。

最初的设计交付包含页面规范与独立交互原型。原型中的按钮仅演示交互，不验证实际归档、封存、账单生成、数据库一致性或权限接口；固定 2026 年 9 月示例也不等于任意月份已验收。随后按第 12 节边界完成实际 Vue 页面首批实现，已运行 typecheck/build 和本地合成接口验收，详细证据见任务记录。原型演示、首批本地验证和完整 P7 真实环境验收必须分别记录。

## 12. 首批页面实施边界（2026-09-20）

用户确认先实现归档页面和接口衔接。三工作区、完整月份日历、日期详情、真实启停/策略/按日对账接入现有接口；不提前实施 P1–P6 的双库结构及归档出账。

因此首批页面的指标采用“已上报日期 / 已结束但未上报 / 出账尚未开放”，而非原型示例中的可出账天数。未上报保持未知，0 条累计也不能证明零业务。日版本、配置时间线、指定日期补齐和账单入口只有说明，不提供模拟成功的操作；现有对账结果只归属最近一次对应日期。

按实际使用反馈收紧顶部：复用应用页标题与全局站点选择器，状态、月份和刷新合并到页签右侧，三项指标采用标签/数值同行的紧凑摘要。点击状态直达任务与策略，最近非空批次保留在提示和任务详情；读取时间放入刷新提示，错误状态仍直接显示旧数据时间。手机页签单独一行、控件合成下一行，长状态自然换行，保持可点击尺寸；空配置或读取失败时刷新入口仍存在。

GET 新增显式能力标志，缺失时保守视为未支持。后续接入新版后端时仍需完成第 11 节对应真实接口验收，不能仅将能力标志改成 true。当前权限、站点选择器及控制协议保持兼容；实际验证和交付状态见[本任务记录](ai-tasks/2026-09-20-log-archive-billing-design.md)。
